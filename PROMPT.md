## Core principles (cross-cutting)

1. **Every server function callable from client returns a `Result<T>` envelope** — never throw to client
2. **Read sheets once with `getDataRange().getValues()`** — batch-write when no merged cells; write cell-by-cell only in merged zones
3. **Lazy resource creation** — folder IDs, sheets, columns auto-create on startup, store in Config sheet
4. **Cache user lookups + computed results** via `CacheService.getScriptCache()` with explicit invalidation
5. **Wrap concurrent mutations in `LockService.getScriptLock()`** with `try/finally { releaseLock() }`
6. **Admin-editable values go in the Config sheet, secrets go in Script Properties** — never hardcoded
7. **User-facing messages in the user's language** + English `Logger.log` for developers
8. **Log every RPC boundary** — `console.log` in client, `Logger.log` in server (entry + exit)
9. **Force text format for numeric fields with leading zeros** — phone, ID card, postal code (`setNumberFormat('@')` + apostrophe prefix)
10. **Recompute critical values server-side** — never trust client-calculated percentages/totals

## Output format for the AI

When suggesting GAS code:
- Reference the rule number/file (e.g., "per `rules/spreadsheet-ops.md` Rule #2")

- Match user-facing message text to the end user's language; keep developer logs in English
- Default to `let`/`const`, ES6+ (V8 runtime is standard now)
- Suggest `LockService` for any function that mutates shared state

# CacheService — Reduce Sheet Round-Trips

## Rule #1: Cache queries that are read often and change rarely

Example: fetching the user profile from the Users sheet on every RPC call — wastes 200ms per call

### ✓ Good

```javascript
function findUserById_(userId) {
  const cache = CacheService.getScriptCache();
  const ck = 'user_' + userId;
  const cached = cache.get(ck);
  if (cached) return JSON.parse(cached);

  const ss = SpreadsheetApp.openById(SPREADSHEET_ID);
  const sh = ss.getSheetByName('Users');
  const user = readSheet_(sh).find(r => String(r.UserID) === String(userId));
  if (user) {
    try { cache.put(ck, JSON.stringify(user), 600); } catch (e) {} // 10 min
  }
  return user;
}
```

---

## Rule #2: Invalidate the cache every time the data changes

```javascript
function invalidateUserCache_(userId) {
  try { CacheService.getScriptCache().remove('user_' + userId); } catch (e) {}
}

function changeMyPassword(callerUserId, oldPwd, newPwd) {
  // ... update sheet ...
  invalidateUserCache_(callerUserId); // 💡
  return { ok: true };
}
```

**Pattern:** every write that touches a row → remove the cache key — forget it and you will spend 30 minutes debugging "why isn't the UI updating"

---

## Rule #3: TTL depends on the nature of the data

| Type | TTL | Reason |
|---|---|---|
| User profile, role | 600s (10 min) | changes rarely, tolerates stale data |
| Config (folder ID, settings) | 3600s (1 hr) | practically never changes |
| Aggregate count (totals, approval queue) | 60s | users expect to see fresh numbers |
| Sensitive (auth token) | 300s | safer + fewer queries |

`CacheService.getScriptCache()` has a max TTL of 21600s (6 hr) — pass a larger value and it does not error, it is capped at 21600

---

## Rule #4: Prefix cache keys to prevent collisions

```javascript
const CK = {
  user: (id) => 'user_' + id,
  config: (key) => 'cfg_' + key,
  recordCount: (folderId) => 'reccnt_' + folderId,
};
```

---

## Rule #5: ScriptCache has a 100KB size limit per key

If the payload is large → split it, or cache only the ID list and fetch the full records one at a time when needed

```javascript
// ✗ Bad — caches the whole array of records, which may be hundreds of rows
cache.put('all_records', JSON.stringify(allRecords)); // may exceed 100KB

// ✓ Good — cache only the list of IDs, read full records from the sheet on use
cache.put('record_ids_pending', JSON.stringify(ids));
```

---

## Rule #6: Wrap `cache.put()` in try/catch — a failure is not critical

```javascript
try {
  cache.put(ck, JSON.stringify(v), 600);
} catch (e) {
  // payload too large, quota full — ignore, not on the critical path
}
```

---

## Rule #7: CacheService vs PropertiesService

| | CacheService | PropertiesService |
|---|---|---|
| TTL | Has one (max 6 hr) | None (permanent) |
| Size | 100KB/key, 24MB total | 9KB/key, 500KB total |
| Use for | query cache, stale reads are OK | flags, config that must persist |
| Performance | fast (in-memory) | slower (persistent) |

**Never use PropertiesService as a cache** — it is a DB, not a cache; there is no TTL

---

## Rule #8: Bind the cache key to the **code version**, not just the data revision

**Why:** the cache key is `'all_' + rev_()` and then you deploy new code that changes the *shape* of the payload — `rev` never moves because the data did not change. The result: the web app keeps eating the old payload out of cache for another 6 hours. You measure the optimisation at `-0.2%` and sit there wondering why it did not get faster

```javascript
// ✗ Bad — new code deployed but the old cache is still being served
var ck = 'all_' + rev_();

// ✓ Good — bump this number every time the payload structure changes
var ALL_CACHE_VERSION = 6;
var ck = 'all_v' + ALL_CACHE_VERSION + '_' + rev_();
```

**Edge case:** a forgotten `ALL_CACHE_VERSION` bump fails completely silently — put it in your deploy checklist next to the version stamp ([deployment-versioning.md](deployment-versioning.md))

# Data Integrity — Prevent Overwrites, Prevent Bulk Deletes, Verify After Editing

This file is about GAS that acts as the **real, non-reversible system of record** (money balances, stock, registration numbers) — a bug in this category does not make the program crash, it makes the **data quietly wrong**

| # | Rule |
|---|---|
| 1 | Force the client to send `rev` on every full overwrite — not sent = reject |
| 2 | A circuit breaker that prevents bulk deletes |
| 3 | Post-save work must sit inside try/catch — never turn a successful save into an error |
| 4 | Server-owned fields must not be overwritten by the client payload |
| 5 | Reconcile must read from **every** place the value is stored |
| 6 | Verify the result by "identity", not by "total" |

---

## Rule #1: Force the client to send `rev` on every full overwrite — not sent = reject

**Why:** this happened in production — a browser tab that had been left sitting for 3 weeks was opened again and synced its stale `localStorage` state back up, wiping 179 bookings in a single instant. The code already had a `rev` guard, but it was written as "if `rev` *is present*, then compare" — an old client that has never heard of the field sails straight through

An optimistic-lock gate that can be bypassed by simply **not sending the field** is not a gate

**Apply this to every state-changing command, not just the save button** — skip / advance / complete / postpone / cancel are all writes too (seen in the wild: the "Postpone" button on a stale card advanced the next installment that was not even due yet, and postponed entries that had already been disabled, because that command never checked the current state the way the other commands did)

- The web page sends **the state it is currently looking at** every time (the row's `rev`, or whatever value it decided from — e.g. the due date of the installment whose button was pressed)
- The server checks **inside the lock** that it still matches the real data and that the entry is still enabled, before writing — on a mismatch, reject and tell the user the data has already changed, ask them to reload
- Write one helper (`assertCurrent_(row, seen)`) and call it from **every** command, then no command can slip through

### ✗ Bad

```javascript
// passes if body.rev is undefined / '' / never sent at all
if (body.rev !== undefined && body.rev !== null && body.rev !== '' &&
    !isNaN(Number(body.rev)) && Number(body.rev) !== curRev) {
  return json_({ ok: false, conflict: true, rev: curRev, state: readState_() });
}
writeState_(body.state);
```

### ✓ Good

```javascript
var curRev = rev_();
var sentRev = Number(body.rev);

// rev not sent = old client / does not know how stale its own data is → reject
if (body.rev === undefined || body.rev === null || body.rev === '' || isNaN(sentRev)) {
  return json_({
    ok: false, conflict: true, rev: curRev, state: readState_(),
    error: 'Save request did not specify a data version — the latest data has already been loaded, please save again'
  });
}
if (sentRev !== curRev) {
  return json_({ ok: false, conflict: true, rev: curRev, state: readState_(),
                 error: 'Someone else saved first — the latest data has already been loaded' });
}
```

**Edge case:** always attach the latest `state` to a conflict response — the client can then merge immediately without firing another round trip (which on GAS = another queue cycle)

---

## Rule #2: A circuit breaker that prevents bulk deletes

**Why:** `rev` only stops "stale data overwriting new data" — it does **not** stop a client-side bug that sends corrupt state along with a perfectly valid `rev` — e.g. empty state because parsing failed. Without a ceiling, a single save can delete the entire database

The ceiling should be set from "normal user behaviour" (a person deleting 1–2 entries at a time), not from the size of the data

### ✓ Good

```javascript
var MAX_DELETES_PER_SAVE = 5;

var deletes = pendingChanges.filter(function (c) { return c.action === 'deleteBooking'; });
if (deletes.length > MAX_DELETES_PER_SAVE && body.confirmBulkDelete !== true) {
  return json_({
    ok: false, bulkDeleteBlocked: true, rev: curRev, state: readState_(),
    deleteCount: deletes.length,
    deleteNames: deletes.slice(0, 10).map(function (c) { return c.name; }),
    error: 'This request will delete ' + deletes.length + ' entries at once — the system has held it back'
  });
}
```

**Edge case:** the unlock path must be something that is "deliberately sent" (`confirmBulkDelete: true`) and there must be **no confirm button in the web UI** that a person can hit by accident — do the real deletion through a custom menu in the sheet instead ([onopen-menu.md](onopen-menu.md))

---

## Rule #3: Post-save work must sit inside try/catch — never turn a successful save into an error

**Why:** once `writeState_()` has written to the sheet = it is committed. If the `refreshSummaries_()` that follows throws, the user sees "save failed" even though the data went in perfectly well → they press it again → duplicate data

### ✗ Bad

```javascript
writeState_(body.state);
refreshSummaries_();      // a throw here = the user sees the save fail
return json_({ ok: true, rev: bumpRev_() });
```

### ✓ Good

```javascript
writeState_(body.state);
var newRev = bumpRev_();

// derived data can be repaired later, but "telling the user the wrong thing" cannot
var summaryError = null;
try {
  refreshSummaries_();
} catch (e) {
  summaryError = String(e && e.message || e);
  Logger.log('[doPost] refreshSummaries_ failed after commit: ' + summaryError);
}
return json_({ ok: true, rev: newRev, summaryError: summaryError });
```

**Edge case:** apply this to **everything that lives after the commit point** — sending mail, writing the audit log, clearing the cache, calling external APIs

---

## Rule #4: Server-owned fields must not be overwritten by the client payload

**Why:** the frontend only knows part of the data. If `writeState_` writes the whole row from the object the client sent, then values the client does not have (an amount paid in from another screen, a status the system computes itself) get blanked out — completely silent, no error

### ✗ Bad

```javascript
rows.push([b.id, b.name, b.kind, b.phone,
           Number(b.paidAmount) || '',           // the client does not know this amount → blanked out
           ST_TH[b.status] || 'unpaid']);    // a status that was already repaired gets reverted
```

### ✓ Good

```javascript
// 1) Read the server-owned values first — keep only the rows that "actually have a value"
//    Rows that are still empty do not need keeping; let the client write the first value in
var keepPaid = {}, keepStatus = {};
existingRows.forEach(function (r) {
  var id = r['code'];
  if (r['amountReceived'] !== '' && r['amountReceived'] != null) keepPaid[id] = r['amountReceived'];
  if (r['status']) keepStatus[id] = r['status'];
});

// 2) Rows where the system already owns a value = locked, do not let the client payload overwrite
var hasOwn = Object.prototype.hasOwnProperty;
var rows = body.state.bookings.map(function (b) {
  return [b.id, b.name, b.kind, b.phone,
          hasOwn.call(keepPaid, b.id)   ? keepPaid[b.id]   : (Number(b.paidAmount) || ''),
          hasOwn.call(keepStatus, b.id) ? keepStatus[b.id] : (ST_TH[b.status] || 'unpaid')];
});
```

**Edge case:** check that the "lock" is bound to a value the server genuinely holds, not a flag that was merely declared — a `locked` flag that is never actually set to `true` is completely silent and behaves as if there were no gate at all

**Edge case 2:** the cleaner path is **do not let the client send these fields at all** — change them through a dedicated endpoint (`action=recordPayment`) that checks permissions and computes server-side ([web-app-rpc.md](web-app-rpc.md) Rule: recompute critical values server-side)

## Rule #5: Reconcile must read from **every** place the value is stored

**Why:** you write a status-repair job for "who has already paid but still shows as outstanding" that reads only the amount column in the main table → it runs and repairs 0 entries, because the broken rows are the ones where the money was recorded in **a separate payment log sheet**, not in that column

Before writing the reconcile, trace first how many paths can write that same value

### ✓ Good

```javascript
function reconcilePaidStatus_(bookingRows, paymentRows) {
  var logPaid = {};
  paymentRows.forEach(function (p) {
    logPaid[p['bookingCode']] = (logPaid[p['bookingCode']] || 0) + (Number(p['amountReceived']) || 0);
  });

  var fixed = 0;
  bookingRows.forEach(function (b) {
    // the money can live in 2 places → take whichever exists, do not add them together (adding = double counting)
    var paid = Number(b['amountReceived']) || logPaid[b['code']] || 0;
    if (paid >= Number(b['amountDue']) && b['status'] !== 'paid') {
      sh.getRange(b._row, ST_COL).setValue('paid');  // one-way upgrade
      fixed++;
    }
  });
  return fixed;
}
```

**Edge case:** a data-repair job should move **one way only** (outstanding → paid), never downgrade automatically — if the logic wrongly upgrades, that mistake can still be audited afterwards, but a wrong downgrade wipes out a status that a person entered by hand

**Edge case 2:** after reconcile runs you must also `bumpRev_()` + invalidate the cache, otherwise the web page keeps serving the old value from cache and it looks like the job did nothing ([cache-service.md](cache-service.md) Rule #2)

---

## Rule #6: Verify the result by "identity", not by "total"

**Why:** you hand a batch of card coupons over to one department, then check "280 coupons · 63,500 baht · 0 remaining" — every check passes **but they are a different batch from the ones actually delivered into the recipient's hand**. The count is right, the identity is wrong, and an aggregate checksum cannot catch that at all

Data that has an "identity" (document number, card number, serial, seat number) must be compared **number by number**

### ✓ Good — an endpoint that checks item by item, callable both before and after the edit

```javascript
function crossCheckOne_(code) {
  var actual = readAssignedNumbers_(code);      // what the system actually holds
  var expect = readRegistryNumbers_(code);      // what the source registry says

  return {
    code: code,
    countMatch: actual.length === expect.length,
    missing: expect.filter(function (n) { return actual.indexOf(n) < 0; }),
    extra:   actual.filter(function (n) { return expect.indexOf(n) < 0; }),
    actual: fmtRuns_(actual),                   // "261-262, 280-289"
    expect: fmtRuns_(expect)
  };
}
```

There is only one acceptable result: `missing` and `extra` **both empty** — a `countMatch: true` on its own does not count

**Edge case:** compress the output into ranges (`261-262, 280-289`) so a human can still catch the mistake by eye — nobody reads a list of 280 numbers laid out one after another

**Edge case 2:** a verification tool that already exists but was never pulled out and used = it does not exist. If you have an endpoint like this, run it **before and after every edit**, then paste the results from both rounds for the user to compare

# Deployment & Versioning (clasp)

## Rule #1: `clasp push` does not change the production web app — you must create a new version of the deployment

**Why:** the classic number-one beginner GAS bug — push the code, open `/exec`, and see nothing new, because a versioned deployment **pins the code at the version you deployed**

| URL | Runs code from | Who can access |
|---|---|---|
| `.../dev` | **HEAD** (the latest pushed code) | only people with script edit rights |
| `.../exec` | **the deployed version** | per `webapp.access` |

### ✓ The correct flow

```bash
clasp push                      # upload the code to HEAD
# test via the /dev URL first
clasp deploy -i <deploymentId> -d "v12 fix pdf margin"   # update the existing deployment → /exec changes
```

---

## Rule #2: Update the **same** deployment (`-i <deploymentId>`) — never run bare `clasp deploy` again

**Why:** `clasp deploy` without `-i` creates a **new** deployment with a **new URL** — the links you already sent to users / embedded in a LINE rich menu / QR code keep pointing at the old deployment running the old code

```bash
# see existing deployments
clasp deployments
# - AKfycb...XYZ @12 - production

# ✓ deploy over the existing one — the URL stays the same
clasp deploy -i AKfycb...XYZ -d "v13 add export excel"
```

In the Apps Script editor: **Deploy → Manage deployments → ✏️ edit → Version: New version → Deploy** (same result)

---

## Rule #3: Use 2 deployments — `dev` and `production`

**Why:** testing on the same URL users really use = users find bugs before you do

```
Deployment "production"  → the URL handed to real users — update only after testing passes
Deployment "staging"     → URL for the testing team — update often
HEAD (/dev)              → developers only — changes on every push
```

Keep both deployment IDs in the project README — prevents mixing up which is which

---

## Rule #4: Record version + date + change summary in the description every time

**Why:** when production breaks, the first question is "what did the latest version change, and which version should we roll back to?" — an empty description answers nothing

```bash
clasp deploy -i <id> -d "2026-08-14 v14: fix leading zero phone (spreadsheet-ops #6.6)"
```

**Rollback:** Manage deployments → edit → pick the old version → Deploy (same URL, code rolls back)

---

## Rule #5: Embed a version string in the code — so you can check which one the user is running

**Why:** when a user reports a bug the question is "which version are you on?" — browser cache can put the frontend and the backend on different versions (see the version stamp topic in `rules/logging-boundaries.md`)

```javascript
const APP_VERSION = 'v14-2026-08-14';

function getAppInfo() {
  return { ok: true, version: APP_VERSION };
}
```

Show the version in the page footer + log it on every important RPC call

---

## Rule #6: `.claspignore` — never push non-source files into Apps Script

**Why:** clasp pushes every file in the folder by default — README, test files, sample `.env` all show up in the Apps Script editor (and every `.js` file becomes runnable server code)

```
# .claspignore
**/**
!*.js
!*.html
!appsscript.json
```

(allowlist-style patterns — name only what you want to push)

---

## Rule #7: Changing `webapp.access` / `executeAs` always requires a new deployment version

**Why:** values in `appsscript.json` take effect at deploy time — editing the file and pushing is not enough, and changing `executeAs` can make Google re-request authorization for all scopes — tell users in advance, or the whole organization panics when the permission screen appears

## Rule #1: store folder IDs in the Config sheet — never hardcode

**Why:** hardcode them in the script and every folder move forces a fresh redeploy — edit the Config sheet instead and it takes effect immediately + anyone with wiki/admin sheet access can see it

### ✓ Good — Config sheet pattern

```
Config sheet:
| Key                  | Value                   |
| TEACHERS_FOLDER_ID   | 1AbC...XYZ              |
| SIGNATURES_FOLDER_ID | 1DeF...UVW              |
| PDF_TEMPLATE_GID     | 96558638                |
```

```javascript
function getConfig_(key) {
  const cache = CacheService.getScriptCache();
  const ck = 'cfg_' + key;
  const cached = cache.get(ck);
  if (cached) return cached;
  const ss = SpreadsheetApp.openById(SPREADSHEET_ID);
  const data = ss.getSheetByName('Config').getDataRange().getValues();
  for (let i = 1; i < data.length; i++) {
    if (data[i][0] === key) {
      const v = String(data[i][1]);
      try { cache.put(ck, v, 3600); } catch (e) {}
      return v;
    }
  }
  return '';
}
```

## Rule #2: lazy creation — create the folder automatically if it does not exist

**Why:** a fresh clone of the project should not require an admin to set it up by hand

```javascript
function ensureSchema() {
  const ss = SpreadsheetApp.openById(SPREADSHEET_ID);
  ensureSheet_(ss, 'Config', ['Key', 'Value']);
  ensureConfigEntry_(ss, 'TEACHERS_FOLDER_ID', () => createDriveFolderIfMissing_('TPM_Teachers'));
  ensureConfigEntry_(ss, 'SIGNATURES_FOLDER_ID', () => createDriveFolderIfMissing_('TPM_Signatures'));
}

function ensureConfigEntry_(ss, key, valueFn) {
  const sh = ss.getSheetByName('Config');
  const data = sh.getDataRange().getValues();
  for (let i = 1; i < data.length; i++) {
    if (data[i][0] === key && data[i][1] !== '' && data[i][1] != null) return data[i][1];
  }
  const v = valueFn();
  sh.appendRow([key, v]);
  SpreadsheetApp.flush();
  return v;
}

function createDriveFolderIfMissing_(name) {
  const folders = DriveApp.getFoldersByName(name);
  if (folders.hasNext()) return folders.next().getId();
  return DriveApp.createFolder(name).getId();
}
```

## Rule #3: return signature/avatar images as base64 dataURL — do not use Drive thumbnail URLs

**Real bug:** the signature preview in the web app does not render (broken image icon)

**Cause:** Drive URLs (`drive.google.com/uc?id=...` or `lh3.googleusercontent.com/...`) require an OAuth cookie — loaded in an `<img>` of a web app deployed with `executeAs: USER_DEPLOYING` they get blocked by CORS or return 403 (because the end user is not signed in to Google in that tab, or has no access to the Drive)

### ✗ Bad — let the client load the URL directly

```javascript
// Server
return { ok: true, signatureUrl: 'https://drive.google.com/uc?id=' + fileId };

// Client
<img src="https://drive.google.com/uc?id=..."> // 💥 broken
```

### ✓ Good — the server fetches the blob and returns a dataURL

```javascript
// Server
function getMySignatureDataUrl(callerUserId) {
  try {
    const caller = requireUser_(callerUserId);
    if (!caller.SignatureFileId) return { ok: true, dataUrl: '' };
    const file = DriveApp.getFileById(caller.SignatureFileId);
    const blob = file.getBlob();
    const mime = blob.getContentType() || 'image/png';
    const b64 = Utilities.base64Encode(blob.getBytes());
    return { ok: true, dataUrl: 'data:' + mime + ';base64,' + b64 };
  } catch (err) {
    return { ok: false, message: err.message };
  }
}

// Client
const res = await rpc('getMySignatureDataUrl', this.user.userId);
if (res.ok && res.dataUrl) {
  this.sigCurrentUrl = res.dataUrl; // use with <img :src="sigCurrentUrl">
}
```

**Pros:**
- No CORS issues — the dataURL is embedded in the page
- No need to share the file (it stays private)
- Works on a web app in every deployment mode

**Cons:**
- base64 is ~33% larger than binary — fine for small images (signature, avatar, logo), not for multi-MB photos
- if you need to show hundreds of images at once → cache the dataURL client-side or use the next approach

## Rule #4: for large images / many images — share ANYONE_WITH_LINK + use a direct URL

```javascript
// Server — set sharing after creating the file
const file = folder.createFile(blob);
try {
  file.setSharing(DriveApp.Access.ANYONE_WITH_LINK, DriveApp.Permission.VIEW);
} catch (e) {
  // domain policy block — the file is still saved, just not publicly linkable
  Logger.log('[saveImage] setSharing failed (likely domain policy): ' + e.message);
}

// return the thumbnail URL
return {
  ok: true,
  thumbUrl: 'https://lh3.googleusercontent.com/d/' + file.getId() + '=w400',
  // or the full URL

};
```

**Trade-off:** anyone-with-link means the content is no longer secret — usable for non-sensitive user-generated content (product photos, cover images); never use it for personal documents

## Rule #4.1: `setSharing(ANYONE_WITH_LINK)` breaks on a school/organization Google Workspace

**Real bug (case study):** the original code runs fine on personal Gmail → deployed to a teacher whose deploy account is `@school.ac.th` and it throws:

```
Exception: Permission denied: DriveApp
```

**Cause:** the Google Workspace admin of the org (school, government agency, large company) set a "**Block external sharing**" or "**Restrict to domain only**" policy — `ANYONE_WITH_LINK` counts as external, so it gets blocked → DriveApp throws immediately

Users see the error when they press save; the app breaks across the board because the exception bubbles up out of the function

### ✗ Bad — assume sharing works + a throw blocks the whole function

```javascript
function uploadImageAndSave(...) {
  const file = folder.createFile(blob);
  file.setSharing(DriveApp.Access.ANYONE_WITH_LINK, DriveApp.Permission.VIEW); // 💥 throw
  saveRowToSheet(file.getId(), file.getUrl()); // never reached
}
```

### ✓ Good — wrap `setSharing` in try/catch + degrade gracefully

```javascript
function uploadImageAndSave(callerUserId, base64, meta) {
  try {
    const file = folder.createFile(blob);

    // try public sharing — if it fails that is fine, the file still exists
    let publicUrl = '';
    try {
      file.setSharing(DriveApp.Access.ANYONE_WITH_LINK, DriveApp.Permission.VIEW);
      publicUrl = 'https://lh3.googleusercontent.com/d/' + file.getId() + '=w400';
    } catch (sharingErr) {
      Logger.log('[upload] setSharing blocked by domain policy: ' + sharingErr.message);
      // fallback: return the file ID and let the client fetch it over the base64 RPC instead
    }

    saveRowToSheet(file.getId(), publicUrl);
    return { ok: true, fileId: file.getId(), publicUrl: publicUrl };
  } catch (err) {
    return { ok: false, message: err.message };
  }
}
```

### ✓ Better — know at deploy time that the domain blocks public sharing → design without it at all

If you know every target user is in the same domain (a school, a company) → **never use `ANYONE_WITH_LINK` in the first place**. Use base64 dataURL over RPC (Rule #3) or share inside the domain only:

```javascript
// Share only within the domain — normally allowed by policy
file.setSharing(DriveApp.Access.DOMAIN_WITH_LINK, DriveApp.Permission.VIEW);
```

or share with specific users:

```javascript
file.addViewer('supervisor@school.ac.th');
```

### Decision tree

```
Must the image be shown in the web app?
├── Yes + every user is in the same domain
│   └── Use base64 dataURL over RPC (Rule #3) — no sharing at all
├── Yes + multiple/external domains + image is not sensitive
│   └── Try ANYONE_WITH_LINK + try/catch fallback
├── Yes + image is sensitive
│   └── base64 dataURL + check permissions on every RPC call
└── No — just store it in Drive
    └── createFile and done — no setSharing needed
```

### How to detect the policy up front

There is no GAS API that queries the policy directly — practical options:
1. **Deploy and test with a test account in the target domain** to see whether `setSharing` throws
2. **Store a flag in the Config sheet** `ALLOW_PUBLIC_SHARING = true/false` — let the admin toggle it to match reality
3. **try/catch + memoize** — if the first attempt fails, remember it in CacheService for a whole day instead of retrying

```javascript
function canPublicShare_() {
  const cache = CacheService.getScriptCache();
  const cached = cache.get('can_public_share');
  if (cached !== null) return cached === '1';

  try {
    // test with a dummy file
    const testFile = DriveApp.createFile('___test_share___', '');
    testFile.setSharing(DriveApp.Access.ANYONE_WITH_LINK, DriveApp.Permission.VIEW);
    testFile.setTrashed(true);
    cache.put('can_public_share', '1', 86400); // 24 hr
    return true;
  } catch (e) {
    cache.put('can_public_share', '0', 86400);
    return false;
  }
}
```

## Rule #6: validate the dataURL server-side before decoding base64

```javascript
function saveImage_(base64DataUrl, folderId, filename) {
  if (!base64DataUrl || base64DataUrl.indexOf('data:image/') !== 0) {
    throw new Error('invalid image data');
  }
  const m = base64DataUrl.match(/^data:(image\/\w+);base64,(.+)$/);
  if (!m) throw new Error('invalid base64 format');
  const mime = m[1];
  const bytes = Utilities.base64Decode(m[2]);

  // max size 5MB
  if (bytes.length > 5 * 1024 * 1024) {
    throw new Error('image larger than 5MB');
  }

  const ext = mime === 'image/jpeg' ? 'jpg' : mime === 'image/png' ? 'png' : 'bin';
  const blob = Utilities.newBlob(bytes, mime, filename + '.' + ext);
  return DriveApp.getFolderById(folderId).createFile(blob);
}
```

## Rule #8: DriveApp scope — use `drive`, not `drive.file`

**Real bug:** an app that takes photos and stores them in Drive declared the narrowest scopes possible, following the "request only what you use" principle:

```json
"oauthScopes": [
  "https://www.googleapis.com/auth/spreadsheets",
  "https://www.googleapis.com/auth/drive.file"
]
```

The moment a photo is saved, `DriveApp.createFolder()` (Rule #2) fails immediately:

```
The declared scopes are not sufficient to call DriveApp.createFolder. The required scope is https://www.googleapis.com/auth/drive
```

**Why:** `drive.file` limits access to files the app created itself, but `DriveApp` does not support that scope at all — the `DriveApp` reference lists `https://www.googleapis.com/auth/drive` as the scope for both `createFile` and `createFolder`, with no alternative

### ✓ Good

```json
"oauthScopes": [
  "https://www.googleapis.com/auth/spreadsheets",
  "https://www.googleapis.com/auth/drive"
]
```

| What you use DriveApp for | scope |
|---|---|
| Write: `createFile`, `createFolder`, `Folder.createFile`, `setSharing`, `setTrashed` | `drive` |
| Read only: `getFileById`, `getFolderById`, `getBlob` | `drive.readonly` |

- During authorization Google warns that the app can reach all of Drive — that is a limitation of `DriveApp`, not a mistake in your code
- If you really need `drive.file`, do not use `DriveApp` — call the Drive REST API yourself (`UrlFetchApp` + `ScriptApp.getOAuthToken()` + scope `script.external_request`) or use the Advanced Drive Service, which requires enabling extra APIs
- Adding a scope later = the owner has to re-authorize once before other users can use that feature

# Dynamic Dropdowns (options that should never be hardcoded)

## Rule: date/year dropdowns — never hardcode them in HTML

**Why:** code that hardcodes `<option value="2024">2024</option>` goes "stale" the moment time passes — a user in 2027 opens the page, sees the old years, and is confused immediately

### ✗ Bad — fixed list

```html
<select x-model="recordForm.year">
  <option value="2567">2567</option>
  <option value="2568">2568</option>
  <option value="2569">2569</option>
</select>
```

### ✓ Good — generate from the current year + merge in the values present in the sheet

```javascript
// inside Alpine data() / state
get yearOptions() {
  // current year + 2 previous + 2 next (Buddhist Era)
  const currentBE = new Date().getFullYear() + 543;
  const generated = [];
  for (let y = currentBE - 2; y <= currentBE + 2; y++) generated.push(y);

  // merge in years that already appear in records (in case a record is older than -2 years)
  const fromData = [...new Set(this.records.map(r => Number(r.Year)).filter(Boolean))];

  // merge + sort desc (newest first) + unique
  return [...new Set([...generated, ...fromData])].sort((a, b) => b - a);
}
```

```html
<select x-model="recordForm.year">
  <template x-for="y in yearOptions" :key="y">
    <option :value="y" x-text="y"></option>
  </template>
</select>
```

---

## Rule: default value = the current year

```javascript
// when initialising the form
recordForm: {
  year: new Date().getFullYear() + 543, // Buddhist Era
  term: this.guessCurrentTerm(),
  // ...
},

guessCurrentTerm() {
  const m = new Date().getMonth() + 1; // 1-12
  // term 1: May-Sep (5-9), term 2: Oct-Mar
  return (m >= 5 && m <= 9) ? 1 : 2;
}
```

## Rule: enum dropdowns built from real data — pull them from the sheet

Example: a "class level" dropdown (P.1, P.2, M.3, ...) — pull from the records that actually exist + add an input field for "a value not yet present"

# Email & Notifications

## Rule #1: Use `MailApp` for send-only — `GmailApp` only when you must read/manage the inbox

**Why:** `GmailApp` requests the `.../auth/gmail` scope (read-write-delete over the whole mailbox) — a scary authorize screen and hard to audit, while `MailApp` only asks for `.../auth/script.send_mail` (send only)

```javascript
// ✓ Send a notification — MailApp is enough
MailApp.sendEmail({
  to: 'admin@school.ac.th',
  subject: '[Grading System] 3 records are waiting for approval',
  htmlBody: '<p>You can review them at <a href="' + APP_URL + '">the Grading System</a></p>',
});
```

---

## Rule #2: Check quota before sending a batch — consumer accounts get only 100/day

| Account | Email/day |
|---|---|
| gmail.com | 100 |
| Google Workspace | 1,500 |

**Why:** a system that sends one email per record hits the quota before you even reach a hundred users — over quota `sendEmail` throws and the rest of the job dies with it

```javascript
function sendBatchNotify_(recipients, subject, htmlBody) {
  const remaining = MailApp.getRemainingDailyQuota();
  if (recipients.length > remaining) {
    Logger.log('[mail] quota not enough: need ' + recipients.length + ' have ' + remaining);
    return { ok: false, message: 'Not enough email quota today (' + remaining + ' left)' };
  }
  // Put all recipients in a single bcc = counts against quota once
  MailApp.sendEmail({ to: Session.getEffectiveUser().getEmail(), bcc: recipients.join(','), subject: subject, htmlBody: htmlBody });
  return { ok: true };
}
```

**Quota-saving trick:** many recipients with identical content → put them all in one `bcc` email / only send separately when the content genuinely differs

---

## Rule #3: Email content in the user's language — short subject with a system prefix + an htmlBody that reads well on mobile

**Why:** most recipients open email on a phone, and automated system mail gets skimmed past easily — a `[SystemName]` prefix makes it filterable/searchable

```javascript
function notifyRecordApproved_(user, record) {
  MailApp.sendEmail({
    to: user.Email,
    subject: '[Grading System] Approved — ' + record.RecordID,
    htmlBody:
      '<div style="font-family:sans-serif;max-width:480px">' +
      '<p>Hello ' + escapeHtml_(user.DisplayName) + '</p>' +
      '<p>Record <b>' + escapeHtml_(record.RecordID) + '</b> has been approved</p>' +
      '<p><a href="' + APP_URL + '?record=' + encodeURIComponent(record.RecordID) + '">Open the record</a></p>' +
      '<hr><p style="color:#888;font-size:12px">Automated email — no reply needed</p>' +
      '</div>',
  });
}
```

Values from the user/sheet inserted into htmlBody must be escaped (prevents HTML injection — same rule as `rules/security.md` Rule #6)

## Rule #4: Error notifications must be throttled — stop flooding the admin's inbox

**Why:** a trigger that runs every 5 minutes and keeps failing = 288 error emails/day — quota gone and the admin stops reading (an ignored notification is no notification)

### ✓ Good — notify about the same issue at most once per hour, via cache

```javascript
function notifyAdminOnce_(jobName, err) {
  const cache = CacheService.getScriptCache();
  const key = 'errnotify_' + jobName;
  if (cache.get(key)) return; // already notified this hour
  cache.put(key, '1', 3600);
  try {
    MailApp.sendEmail({
      to: getConfig_('ADMIN_EMAIL'),
      subject: '[Grading System] ⚠️ ' + jobName + ' failed',
      body: 'Error: ' + (err && err.message) + '\n\nStack:\n' + (err && err.stack) +
            '\n\nSee the log: Apps Script editor → Executions',
    });
  } catch (mailErr) {
    Logger.log('[notifyAdminOnce] cannot send mail: ' + mailErr.message);
  }
}
```

- Keep the admin email in the Config sheet (`ADMIN_EMAIL`) — changing the person responsible needs no code edit
- Sending an error email needs its own try/catch — never let the notification break the main job

```javascript
MailApp.sendEmail({
```

## Rule #1: Result envelope for every server function — never throw

See `rules/web-app-rpc.md` Rule #1 — in short:

```javascript
function checkIn(callerUserId, visitId, lat, lng) {
```

## Rule #5: user-actionable error messages — not "Error"

### ✗ Bad


## Rule #6: common GAS error messages that need translating

| GAS native | Translate for the user |
|---|---|
| `Service error: Spreadsheet` | "The Sheet service is temporarily unavailable, please try again" + log the real error |
| `Service Spreadsheets failed while accessing document` | "Could not open the document — check permissions" |
| `Exception: Address unavailable` | "Could not reach the external API, please try again" |
| `Lock wait timeout` | "The system is handling other requests, please retry in a moment" |
| `Exceeded maximum execution time` | "Processing took too long — split the work into smaller batches" |

```javascript
function translateError_(err) {
  const msg = String(err.message || err);
  if (msg.includes('Service error')) {
    return 'The Sheet service is temporarily unavailable, please try again';
  }
  if (msg.includes('Lock')) {
    return 'The system is handling other requests, please retry in a moment';
  }
  if (msg.includes('execution time')) {
    return 'Processing took too long, please try again';
  }
  return msg;
}
```

## Rule #7: show errors in a modal on the client, not in the console

## Rule #8: retry pattern for transient errors

```javascript
async function rpcWithRetry(name, ...args) {
  const maxAttempts = 3;
  let lastErr;
  for (let i = 0; i < maxAttempts; i++) {
    try {
      const res = await rpc(name, ...args);
      if (res.ok) return res;
      // if the error is lock/transient — retry
      if (/lock|busy|timeout|service/i.test(res.message)) {
        await sleep(1000 * (i + 1));
        continue;
      }
      return res; // permanent error — do not retry
    } catch (e) {
      lastErr = e;
      await sleep(1000 * (i + 1));
    }
  }
  return { ok: false, message: 'Could not reach the system, please try again later' };
}

const sleep = (ms) => new Promise(r => setTimeout(r, ms));
```

## Context: why the frontend must be separated from GAS

A GAS web app runs inside a sandboxed iframe on `*.googleusercontent.com` — Google blocks many APIs that a normal website can use:

| API | Status in the GAS iframe |
|---|---|
| `getUserMedia()` (camera/mic) | ❌ blocked (Permissions Policy block) |
| `navigator.geolocation` | ⚠️ asks for permission and sometimes still fails |
| `navigator.clipboard.writeText` | ⚠️ requires a user gesture, sometimes fails |
| `IndexedDB`, `localStorage` | ⚠️ available but scoped to the iframe origin (does not persist across deploys) |
| `Notification API` (push) | ❌ blocked |
| `Service Worker` (PWA, offline) | ❌ blocked |
| File System Access API | ❌ blocked |
| WebRTC | ❌ blocked |
| Custom domain | ❌ not possible |
| Service Workers / PWA installable | ❌ not possible |
| Good Open Graph / SEO | ❌ (the iframe wrapper hides most of it) |

**Workaround:** move the frontend to **GitHub Pages / Netlify / Vercel**, a normal origin — full capabilities like any regular website + call GAS as an API backend through `fetch`

## Rule #1: GAS endpoint — accept POST `text/plain` to avoid the CORS preflight

**Important:** GAS **does not answer `OPTIONS` preflight** — if the client sends `Content-Type: application/json` the browser sends a preflight first → fail

### ✓ Good — use `text/plain` (simple request, no preflight)

```javascript
// Server (Code.gs)
const RPC_ALLOWED = ['login', 'saveRecord', 'uploadImage', 'getRecords'];

function doPost(e) {
  try {
    const payload = JSON.parse(e.postData.contents || '{}');
    const { fn, args } = payload;
    if (!RPC_ALLOWED.includes(fn)) {
      return jsonOut_({ ok: false, message: 'forbidden function: ' + fn });
    }
    const result = globalThis[fn].apply(null, args || []);
    return jsonOut_(result);
  } catch (err) {
    Logger.log('[doPost] EXCEPTION ' + (err.stack || err));
    return jsonOut_({ ok: false, message: err.message });
  }
}

function doGet(e) {
  // health check / handshake
  return jsonOut_({ ok: true, service: 'TPM API', version: APP_VERSION });
}

function jsonOut_(obj) {
  return ContentService.createTextOutput(JSON.stringify(obj))
    .setMimeType(ContentService.MimeType.JSON);
}
```

```javascript
// Client (GitHub Pages)
const GAS_URL = 'https://script.google.com/macros/s/AKfycb.../exec';

async function rpc(fn, ...args) {
  const t0 = Date.now();
  console.log('→ RPC', fn, args);
  const res = await fetch(GAS_URL, {
    method: 'POST',
    // ⚠️ never use application/json — it triggers a preflight
    headers: { 'Content-Type': 'text/plain;charset=utf-8' },
    body: JSON.stringify({ fn, args }),
    redirect: 'follow', // GAS redirects on the first call
  });
  const data = await res.json();
  console.log('← RPC', fn, (Date.now() - t0) + 'ms', data);
  return data;
}
```

## Rule #3: every request must send an auth token in the payload

The GAS endpoint is public → anyone can hit it → **you must verify the session on every call**

```javascript
// Client — keep the token after login
let SESSION_TOKEN = localStorage.getItem('token') || '';

async function rpc(fn, ...args) {
  const res = await fetch(GAS_URL, {
    method: 'POST',
    headers: { 'Content-Type': 'text/plain;charset=utf-8' },
    body: JSON.stringify({ fn, args, token: SESSION_TOKEN }),
  });
  return res.json();
}

async function login(username, password) {
  const res = await rpc('login', username, password);
  if (res.ok) {
    SESSION_TOKEN = res.token;
    localStorage.setItem('token', res.token);
  }
  return res;
}
```

```javascript
// Server — verify on every function except login
function doPost(e) {
  const payload = JSON.parse(e.postData.contents || '{}');
  const { fn, args, token } = payload;

  const PUBLIC_FNS = ['login'];
  let caller = null;
  if (!PUBLIC_FNS.includes(fn)) {
    caller = requireSession_(token); // throws if the token is invalid/expired
  }

  // pass caller as the first arg instead of userId
  const result = globalThis[fn].apply(null, caller ? [caller, ...args] : args);
  return jsonOut_(result);
}
```

## Rule #5: compress the image before sending — the RPC payload limit is ~50MB but the network is slow

```javascript
async function compressImage(dataUrl, maxWidth = 1280, quality = 0.85) {
  return new Promise((resolve) => {
    const img = new Image();
    img.onload = () => {
      const ratio = Math.min(maxWidth / img.width, 1);
      const canvas = document.createElement('canvas');
      canvas.width = Math.round(img.width * ratio);
      canvas.height = Math.round(img.height * ratio);
      canvas.getContext('2d').drawImage(img, 0, 0, canvas.width, canvas.height);
      resolve(canvas.toDataURL('image/jpeg', quality));
    };
    img.src = dataUrl;
  });
}
```

Typical size: a 12MP iPhone camera photo is ~3-5MB → compressed to 1280px it comes down to 200-400KB

## Rule #8.1: multi-account login — append `/u/0/` or `?authuser=` to prevent "unable to open this file right now"

**Real bug:** a user signed into several Google accounts on one machine (e.g. personal + work + school) opens the GAS link and sees:

> **Sorry, unable to open this file right now**
> Please check the address and try again

**Cause:** Google does not know which account to use — the first account (the default `/u/0/`) may not be the one with access to the web app (if it is deployed as `Anyone within domain` or `Anyone with Google account`)

### ✓ Fix for users

Append to the `/exec` URL:

| Format | Use when |
|---|---|
| `.../exec/usp=sharing` | the usual case — Google picks the account |
| `.../exec?authuser=0` | force the default account (the first one signed in) |
| `.../exec?authuser=1` | the 2nd account |
| `.../exec?authuser=user@gmail.com` | explicit email — the clearest option |
| `https://script.google.com/u/1/macros/s/<id>/exec` | inline `/u/<index>/` in the path |

**Recommended:** send links as `?authuser=<email>` to users who have registered.

```
https://script.google.com/macros/s/AKfycb.../exec?authuser=teacher@school.ac.th
```

### ✓ Fix for developers — generate links with authuser embedded

If your system knows the user email (after login) — build the link with authuser attached every time you send it:

```javascript
// Server (GAS)
function getDeployedUrl_(forUserEmail) {
  const base = ScriptApp.getService().getUrl(); // .../exec
  if (forUserEmail) {
    return base + '?authuser=' + encodeURIComponent(forUserEmail);
  }
  return base;
}

// use in notifications sent to users
function sendApprovalNotification_(email, recordId) {
  const url = getDeployedUrl_(email) + '&action=approve&id=' + recordId;
  MailApp.sendEmail({
    to: email,
    subject: 'Approval request pending',
    htmlBody: `<a href="${url}">Open to approve</a>`,
  });
}
```

### ✓ Fix for users who already hit the error

If clicking the link in LINE/email now shows an error:

1. **Easiest** — copy the URL → open a fresh Incognito window → sign in to the target account → paste
2. **Same browser** — `chrome://settings/people` or the profile icon at the top right → switch the target account to default → retry
3. **Add `/u/<index>/`** to the URL — index 0 = the first account signed in, 1 = the second, ...
4. **Set `?authuser=<email>`** at the end of the URL — the surest fix because it names the email directly

### Page UX hint — show guidance when a user hits the error

If a user pastes a malformed URL → the server returns an HTML guide instead of a blank error:

## Rule #11: error handling including CORS / network errors

```javascript
async function rpc(fn, ...args) {
  try {
    const res = await fetch(GAS_URL, {
      method: 'POST',
      headers: { 'Content-Type': 'text/plain;charset=utf-8' },
      body: JSON.stringify({ fn, args, token: SESSION_TOKEN }),
    });
    if (!res.ok) {
      throw new Error('HTTP ' + res.status);
    }
    const text = await res.text();
    if (!text || text.trim().startsWith('<')) {
      // got HTML back = GAS login page = wrong deploy setting
      throw new Error('GAS endpoint misconfigured (returned HTML instead of JSON) — check Execute as / Who has access');
    }
    return JSON.parse(text);
  } catch (err) {
    console.error('✗ RPC', fn, err);
    // network error / parse error / CORS
    return { ok: false, message: 'Could not reach the server: ' + err.message };
  }
}
```

# HtmlService & Frontend

## Rule #1: `<meta viewport>` must live in the `<head>` of a `.html` file — never in a `.gs`

**Bug AI assistants love to make:** some AIs that generate a GAS web app put the viewport meta tag in as a string inside a `.gs` file:

### ✗ Bad — inside .gs, does not work

```javascript
// Code.gs
function doGet() {
  const html = '<meta name="viewport" content="width=device-width, initial-scale=1.0">' +
               '<div>...</div>';
  return HtmlService.createHtmlOutput(html);
}
```

Or they try to inject it through a function:

```javascript
function getViewport() {
  return '<meta name="viewport" content="width=device-width, initial-scale=1.0">';
}
```

**Why it does not work:**
- `HtmlService` wraps your HTML in an iframe (`googleusercontent.com/...`) — a meta tag sitting in `<body>`, or injected at runtime, is ineffective because browsers only parse the viewport during the initial HTML render
- string concat in `.gs` often escapes incorrectly and mangles the tag
- the iframe parent is the Google Apps Script wrapper — we have no permission to change the parent's viewport

What you see: the web app opens on mobile at a tiny size and you have to pinch-zoom every time

### ✓ Good — in the `<head>` of the `.html` file

```html
<!-- Index.html -->
<!DOCTYPE html>
<html lang="th">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My GAS Web App</title>
</head>
<body>
  <!-- ... -->
</body>
</html>
```

```javascript
// Code.gs
function doGet() {
  return HtmlService.createHtmlOutputFromFile('Index')
    .setTitle('My GAS Web App')
    .addMetaTag('viewport', 'width=device-width, initial-scale=1.0'); // optional reinforcement
}
```

**Use `HtmlOutput`'s `addMetaTag()`** — Google injects it into the `<head>` of the iframe wrapper too (defense in depth)

## Rule #2: a viewport that covers every case


# LockService — Concurrency Control

## Rule #1: Wrap mutations that multiple users can collide on in `LockService.getScriptLock()`

**Why:** GAS runs functions in parallel — two users clicking "Generate PDF" at the same moment can:
- create a duplicate temp sheet name
- overwrite the same row
- export a PDF while the template has not been flushed yet

### ✓ Good

```javascript
function generatePdfForRecord(callerUserId, rowIndex) {
  const lock = LockService.getScriptLock();
  if (!lock.tryLock(30000)) {
    throw new Error('The system is processing another request, please try again in a moment');
  }
  try {
    // ... mutations that must be atomic ...
    return { ok: true, /* ... */ };
  } catch (err) {
    return { ok: false, message: err.message };
  } finally {
    lock.releaseLock(); // **mandatory in finally**
  }
}
```

---

## Rule #2: Pick the right lock scope

| Lock | Scope | Use when |
|---|---|---|
| `getScriptLock()` | Whole script (cross-user) | Mutations that must be atomic system-wide (PDF gen, transaction) |
| `getDocumentLock()` | That one container document only | Bound script that modifies the active doc |
| `getUserLock()` | That one user only | Stops a user spamming the same button repeatedly |

Most of the time you want `getScriptLock()` — pick `getUserLock()` only when per-user rate limiting is enough and there is no cross-user race condition to prevent

---

## Rule #3: Pick a sensible `tryLock` timeout — never 0, never oversized

- **0ms** — fails instantly if anyone holds it → users hit errors often, bad UX
- **30000ms (30s)** — long enough to wait, but not long enough for the user to feel frozen
- **> 5 minutes** — more than half the execution quota (6 min); leave it open that long and the whole script dies

### ✓ Standard values

```javascript
const TIMEOUT_PDF = 30000;       // PDF gen 30s
const TIMEOUT_QUICK_WRITE = 5000;  // append row 5s
const TIMEOUT_RARE_BATCH = 60000;  // import 100 rows 1 min
```

---

## Rule #4: Always use `finally { lock.releaseLock(); }` — even on error

**Real bug:** throw before releaseLock with no finally — the lock sticks for 6 minutes until the script times out — every request after that point fails tryLock

```javascript
// ✗ Bad
const lock = LockService.getScriptLock();
lock.waitLock(30000);
doStuff(); // if this throws → the lock sticks!
lock.releaseLock();

// ✓ Good
const lock = LockService.getScriptLock();
if (!lock.tryLock(30000)) throw new Error('busy');
try {
  doStuff();
} finally {
  lock.releaseLock();
}
```

---

## Rule #5: **Never** hold the lock around `UrlFetchApp` or any long-running trigger

**Why:** every millisecond inside the lock = blocking other users

### ✗ Bad

```javascript
const lock = LockService.getScriptLock();
lock.waitLock(30000);
try {
```

# Logging at Data Boundaries

## Rule #1: Log both sides of every RPC boundary — client + server

**Why:** when a bug reports "I hit save and got an unknown error" — without logs at the boundary you cannot tell:
- what the payload looked like leaving the client
- what arrived at the server (missing fields? wrong type?)
- what the server returned
- whether the client interpreted the return correctly

User reports bug → ask for a "console screenshot", get it instantly (F12 → Console)

---

## Rule #2: Client — `console.log` before sending + after receiving every RPC

### ✓ Good — wrap `rpc()` so logging is automatic

```javascript
function rpc(name, ...args) {
  const t0 = Date.now();
  console.log('→ RPC', name, args);
  return new Promise((resolve, reject) => {
    google.script.run
      .withSuccessHandler((res) => {
        console.log('← RPC', name, (Date.now() - t0) + 'ms', res);
        resolve(res);
      })
      .withFailureHandler((err) => {
        console.error('✗ RPC', name, (Date.now() - t0) + 'ms', err);
        reject(err);
      })
      [name](...args);
  });
}
```

What you see in the Console:

```
→ RPC saveRecord ["U002", {folderId: "...", totalStudents: 20, ...}]
← RPC saveRecord 312ms {ok: true, recordId: "REC1234..."}
```

On a bug — you immediately see where the payload changed or whether the server was slow

---

## Rule #3: Server — `Logger.log` entry + exit for every function the client calls

```javascript
function saveRecord(callerUserId, payload) {
  Logger.log('[saveRecord] in caller=' + callerUserId + ' keys=' + Object.keys(payload || {}).join(','));
  try {
    const caller = requireUser_(callerUserId);
    // ... mutation ...
    Logger.log('[saveRecord] out ok recordId=' + recordId);

    return { ok: false, message: err.message };

}
```

**Standard format:**
- `[FuncName] in <key params>` — entry
- `[FuncName] step:<name>` — important step (read DB, validate, write, external API)
- `[FuncName] out ok <key result>` — success
- `[FuncName] out ERR <message>` — error

# Long-running Jobs (exceeding the 6-minute limit)

## Rule #1: A job over ~5 minutes must be designed as batch + resume — never hope it finishes in time

**Why:** GAS cuts an execution at 6 minutes (30 seconds for a custom function) with no warning — a job processing 10,000 rows that "used to finish in time" breaks as soon as the data grows, and breaking halfway = half-written data

**Design principle:** every iteration must be idempotent (re-running the same row does no harm) + store a checkpoint of how far it got

---

## Rule #2: checkpoint pattern — keep the position in Script Properties + set a continuation trigger

### ✓ Good — a skeleton that works for any batch job

```javascript
const TIME_BUDGET_MS = 4.5 * 60 * 1000; // margin against the 6-minute limit

function processAllRecords() {
  const props = PropertiesService.getScriptProperties();
  const start = Date.now();
  let cursor = parseInt(props.getProperty('JOB_CURSOR') || '2'); // first data row

  const sh = SpreadsheetApp.openById(getConfig_('SPREADSHEET_ID')).getSheetByName('Records');
  const lastRow = sh.getLastRow();
  Logger.log('[job] resume at row ' + cursor + ' / ' + lastRow);

  while (cursor <= lastRow) {
    if (Date.now() - start > TIME_BUDGET_MS) {
      props.setProperty('JOB_CURSOR', String(cursor));
      scheduleContinuation_('processAllRecords');
      Logger.log('[job] checkpoint at row ' + cursor + ' — continuing in next run');
      return;
    }
    processOneRow_(sh, cursor); // must be idempotent
    cursor++;
  }

  // job finished — clear state + trigger
  props.deleteProperty('JOB_CURSOR');
  clearContinuation_('processAllRecords');
  Logger.log('[job] done ' + (lastRow - 1) + ' rows');
}

function scheduleContinuation_(handlerName) {
  clearContinuation_(handlerName); // prevent duplicate triggers (see rules/triggers.md Rule #1)
  ScriptApp.newTrigger(handlerName).timeBased().after(60 * 1000).create();
}

function clearContinuation_(handlerName) {
  ScriptApp.getProjectTriggers()
    .filter(t => t.getHandlerFunction() === handlerName)
    .forEach(t => ScriptApp.deleteTrigger(t));
}
```

**3 landmines you must not miss:**
1. **Leave a margin** — cut off at 4.5 minutes, not 5.9 (writing the checkpoint + creating the trigger also take time)
2. **Delete the trigger when done** — otherwise it keeps running empty every minute until the quota is gone
3. **The iteration must be idempotent** — the script may die after processing a row but before writing the checkpoint → that row runs again

---

## Rule #3: Never process inside an RPC the user is waiting on — return "accepted" and work in the background

**Why:** `google.script.run` hits the same 6-minute limit, and the user should not stare at a spinning screen for 5 minutes

### ✓ Good — submit + poll status

```javascript
// RPC: take the command, reply immediately
function startExportJob(callerUserId) {
  const caller = requireUser_(callerUserId);
  PropertiesService.getScriptProperties().setProperties({
    'EXPORT_STATUS': 'running',
    'EXPORT_PROGRESS': '0',
  });
  scheduleContinuation_('runExportJob'); // starts within ~1 minute
  return { ok: true, message: 'Processing started — you will be notified when it is done' };
}

// RPC: the client polls every 5s
function getExportStatus(callerUserId) {
  const p = PropertiesService.getScriptProperties();
  return {
    ok: true,
    status: p.getProperty('EXPORT_STATUS') || 'idle',
    progress: parseInt(p.getProperty('EXPORT_PROGRESS') || '0'),
    fileUrl: p.getProperty('EXPORT_FILE_URL') || null,
  };
}
```

A finished job should also notify another channel (email / LINE — see `rules/email-notifications.md`), in case the user already closed the page

---

## Rule #4: Reduce work per iteration before thinking about batching

**Why:** most jobs that "exceed 6 minutes" are really N+1 round-trips — fix them per `rules/spreadsheet-ops.md` Rule #1 (bulk read) + write in batch and they usually drop well under a minute

Checklist before building a continuation pattern:
- [ ] Did you read the sheet once with `getDataRange().getValues()`?
- [ ] Can you write back in a batch (`setValues` over a range with no merged cells) instead of per cell?
- [ ] Are external fetches using `fetchAll`? (`rules/urlfetch-external-api.md` Rule #3)
- [ ] Is there timing log showing which step is expensive? (`rules/testing-debugging.md` Rule #9)

## Rule #1: use the `{{KEY}}` placeholder pattern in the template sheet

**Why:** the template can be built comfortably through the Sheets UI (formatting, fonts, alignment) without writing any layout code

```javascript
const FIELD_TO_PLACEHOLDER = {
  TeacherName: 'TEACHER_NAME',
  SubjectName: 'SUBJECT_NAME',
  // ...
};

function fillPlaceholders_(tempSheet, mapping) {
  const range = tempSheet.getDataRange();
  const values = range.getValues();
  for (let r = 0; r < values.length; r++) {
    for (let c = 0; c < values[r].length; c++) {
      const orig = values[r][c];
      if (typeof orig !== 'string' || orig.indexOf('{{') < 0) continue;
      let next = orig;
      for (const k in mapping) {
        if (next.indexOf('{{' + k + '}}') >= 0) {
          next = next.split('{{' + k + '}}').join(String(mapping[k] == null ? '' : mapping[k]));
        }
      }
      if (next !== orig) {
        try {
          tempSheet.getRange(r + 1, c + 1).setValue(next);
        } catch (e) {
          Logger.log('skip r=' + (r + 1) + ' c=' + (c + 1) + ': ' + e.message);
        }
      }
    }
  }
}
```

**Never use `range.setValues()`** — most templates contain merged cells (see `rules/spreadsheet-ops.md` Rule #2)

## Rule #2: copy template → temp sheet → export → delete temp

**Why:** never edit the template in place (it affects other users) — always copy first

```javascript
function generatePdfForRecord(callerUserId, rowIndex) {
  const lock = LockService.getScriptLock();
  if (!lock.tryLock(30000)) throw new Error('Another PDF is being generated. Please retry');
  let tempSheet = null;
  try {
    const ss = SpreadsheetApp.openById(SPREADSHEET_ID);
    const tpl = ss.getSheetByName('PdfTemplate');
    if (!tpl) throw new Error('template sheet not found');
    tempSheet = tpl.copyTo(ss);
    tempSheet.setName('__pdf_temp_' + Date.now());
    tempSheet.showSheet();

    fillPlaceholders_(tempSheet, mapping);
    SpreadsheetApp.flush();

    const pdfBlob = exportSheetAsPdf_(ss.getId(), tempSheet.getSheetId(), 'output');
    // ... save blob to Drive ...
    return { ok: true, pdfFileId: file.getId(), pdfUrl: file.getUrl() };
  } catch (err) {
    Logger.log('[PDF] ' + (err.stack || err));
    return { ok: false, message: err.message };
  } finally {
    if (tempSheet) {
      try { SpreadsheetApp.openById(SPREADSHEET_ID).deleteSheet(tempSheet); } catch (e) {}
    }
    lock.releaseLock();
  }
}
```

## Rule #3: export PDF via UrlFetch + OAuth token (not DriveApp)

`SpreadsheetApp` has no `exportAsPdf()` — you must fetch the `/export?format=pdf` URL

```javascript
function exportSheetAsPdf_(ssId, gid, filename) {
  const url = 'https://docs.google.com/spreadsheets/d/' + ssId + '/export?' + [
    'format=pdf',
    'gid=' + gid,
    'portrait=true',
    'fitw=true',           // fit the content to the page width
    'size=A4',
    'gridlines=false',
    'printtitle=false',
    'sheetnames=false',
    'pagenumbers=false',
    'top_margin=0.5',
    'bottom_margin=0.5',
    'left_margin=0.5',
    'right_margin=0.5',
  ].join('&');
  const token = ScriptApp.getOAuthToken();
  const resp = UrlFetchApp.fetch(url, {
    headers: { Authorization: 'Bearer ' + token },
    muteHttpExceptions: true,
  });
  if (resp.getResponseCode() !== 200) {
    throw new Error('PDF export failed: HTTP ' + resp.getResponseCode());
  }
  return resp.getBlob().setName(filename + '.pdf');
}
```

## Rule #4: insertImage anchor = always top-left — the cell alignment has no effect

**Real bug:** set horizontal align = right on a cell that holds the image placeholder → the image is still flush left, because the anchor sits at the top-left of the cell

### ✓ Good — compute the offset yourself

```javascript
function insertSignatureAtPlaceholder_(sheet, placeholder, signatureBlob) {
  const pos = findCellByExact_(sheet, placeholder);
  if (!pos) return;

  const cell = sheet.getRange(pos.row, pos.col);
  const hAlign = String(cell.getHorizontalAlignment() || 'left').toLowerCase();
  const vAlign = String(cell.getVerticalAlignment() || 'top').toLowerCase();
  cell.setValue('');

  const img = sheet.insertImage(signatureBlob, pos.col, pos.row);
  const w0 = img.getWidth(), h0 = img.getHeight();
  const MAX = { width: 120, height: 40 };
  const ratio = Math.min(MAX.width / w0, MAX.height / h0, 1);
  const w = Math.round(w0 * ratio);
  const h = Math.round(h0 * ratio);
  img.setWidth(w).setHeight(h);

  const colW = sheet.getColumnWidth(pos.col);
  const rowH = sheet.getRowHeight(pos.row);
  let xOff = 0, yOff = 0;
  if (hAlign === 'right')        xOff = Math.max(0, colW - w);
  else if (hAlign === 'center')  xOff = Math.max(0, Math.round((colW - w) / 2));
  if (vAlign === 'bottom')       yOff = Math.max(0, rowH - h);
  else if (vAlign === 'middle')  yOff = Math.max(0, Math.round((rowH - h) / 2));
  img.setAnchorCellXOffset(xOff).setAnchorCellYOffset(yOff);
}

function findCellByExact_(sheet, needle) {
  const values = sheet.getDataRange().getValues();
  for (let r = 0; r < values.length; r++) {
    for (let c = 0; c < values[r].length; c++) {
      if (String(values[r][c]).trim() === needle) return { row: r + 1, col: c + 1 };
    }
  }
  return null;
}
```

## Rule #5: preserve the image aspect ratio — never stretch

**Why:** a signature stretched from a square into a long horizontal box looks distorted

```javascript
// ✗ Bad
img.setWidth(180).setHeight(50); // stretch fixed

// ✓ Good — fit inside the max box while preserving the ratio
const ratio = Math.min(MAX.width / w0, MAX.height / h0, 1);
img.setWidth(Math.round(w0 * ratio)).setHeight(Math.round(h0 * ratio));
```

## Rule #6: trim the white border off the image before upload (signature canvas)

**Why:** if the user signs in the bottom-left corner of a 600×200 canvas but uploads the whole canvas — the image is mostly whitespace, so once inserted into the PDF it covers other rows

### ✓ Good — crop before sending

```javascript
function trimCanvasToInk(srcCanvas, padding = 8) {
  const ctx = srcCanvas.getContext('2d');
  const img = ctx.getImageData(0, 0, srcCanvas.width, srcCanvas.height).data;
  let minX = srcCanvas.width, minY = srcCanvas.height, maxX = -1, maxY = -1;
  for (let y = 0; y < srcCanvas.height; y++) {
    for (let x = 0; x < srcCanvas.width; x++) {
      if (img[(y * srcCanvas.width + x) * 4 + 3] > 0) { // alpha > 0
        if (x < minX) minX = x;
        if (y < minY) minY = y;
        if (x > maxX) maxX = x;
        if (y > maxY) maxY = y;
      }
    }
  }
  if (maxX < 0) return null; // empty canvas
  minX = Math.max(0, minX - padding);
  minY = Math.max(0, minY - padding);
  maxX = Math.min(srcCanvas.width - 1, maxX + padding);
  maxY = Math.min(srcCanvas.height - 1, maxY + padding);
  const w = maxX - minX + 1, h = maxY - minY + 1;
  const out = document.createElement('canvas');
  out.width = w; out.height = h;
  const octx = out.getContext('2d');
  octx.fillStyle = 'white';
  octx.fillRect(0, 0, w, h);
  octx.drawImage(srcCanvas, minX, minY, w, h, 0, 0, w, h);
  return out.toDataURL('image/png');
}
```

## Rule #9: locale-aware date formatting — use the same helper everywhere

**Why:** dates in the Sheet are stored as a `Date` object or an ISO string — embedding them straight into the template produces `Mon May 28 2026 12:34:56 GMT+0700`, which nobody can read

### ✓ Good — one helper for every date placeholder

```javascript
// locale month names — swap in the arrays your users expect
const THAI_MONTHS = ['Jan','Feb','Mar','Apr','May','Jun',
                     'Jul','Aug','Sep','Oct','Nov','Dec'];
const THAI_MONTHS_FULL = ['January','February','March','April','May','June',
                          'July','August','September','October','November','December'];

function formatThaiDate_(input, opts) {
  if (!input) return '';
  const d = (input instanceof Date) ? input : new Date(input);
  if (isNaN(d.getTime())) return '';
  const day = d.getDate();
  const month = (opts && opts.full) ? THAI_MONTHS_FULL[d.getMonth()] : THAI_MONTHS[d.getMonth()];
  const year = d.getFullYear() + 543; // CE -> BE (Buddhist Era year)
  return day + ' ' + month + ' ' + year;
}

function formatThaiDateTime_(input) {
  const d = (input instanceof Date) ? input : new Date(input);
  if (isNaN(d.getTime())) return '';
  const hh = String(d.getHours()).padStart(2, '0');
  const mm = String(d.getMinutes()).padStart(2, '0');
  return formatThaiDate_(d) + ' ' + hh + ':' + mm;
}

// Usage in the mapping
mapping['TEACHER_DATE']  = formatThaiDate_(record.Timestamp);             // "28 May 2569"
mapping['ACADEMIC_DATE'] = formatThaiDate_(record.AcademicApprovedAt);
mapping['CREATED_AT']    = formatThaiDateTime_(record.Timestamp);         // "28 May 2569 14:30"
```

**Edge case:** if the Sheet field is "not approved yet" (an empty value) → the helper returns `''` instead of throwing — the PDF placeholder stays a blank string, which looks clean

**Caveat:** do not use `Utilities.formatDate(date, 'Asia/Bangkok', 'd MMM yyyy')` — the Apps Script locale string emits month names in the script locale, not the one your users read, so keep your own month arrays

## Rule #10: cache the PDF — get-or-generate pattern in separate endpoints

**Why:** generating a PDF takes 3-5 seconds — a user reopening the same record should not wait for a regeneration every time

### ✓ Good — 2 separate endpoints

```javascript
// Endpoint #1: read the PDF (use the cache when present)
function getRecordPdfInfo(callerUserId, rowIndex) {
  try {
    const caller = requireUser_(callerUserId);
    const record = readRecord_(rowIndex);
    if (!record) throw new Error('record not found');
    if (caller.Role === 'teacher' && String(record.TeacherUserID) !== String(caller.UserID)) {
      throw new Error('permission denied');
    }

    // ⚡ cache hit — return immediately (no lock, no generation)
    if (record.PdfFileId) {
      return {
        ok: true,
        pdfFileId: record.PdfFileId,
        pdfUrl: record.PdfUrl,
        downloadUrl: 'https://drive.google.com/uc?export=download&id=' + record.PdfFileId,
      };
    }

    // guard before falling back
    if (record.AcademicStatus !== 'PASSED' || record.DirectorStatus !== 'PASSED') {
      throw new Error('All approvals must be complete before a PDF can be generated');
    }

    // cache miss — generate a new one (slow path)
    return generatePdfForRecord(callerUserId, rowIndex);
  } catch (err) {
    return { ok: false, message: err.message };
  }
}

// Endpoint #2: force regeneration (the user clicks the "Regenerate" button)
// -> calls generatePdfForRecord() directly
//   that function trashes the old file first (Rule #7) then generates a new one
```

### ✓ Client-side pattern

```javascript
// "Open PDF" — fast path, load the cache immediately if present
async doOpenPdf() {
  const rec = this.modal.record;
  if (rec.PdfUrl) { window.open(rec.PdfUrl); return; }  // short-circuit on the client too

  if (res.ok) window.open(res.pdfUrl);
}
```

**Trade-off:** the PDF cache can go stale if the record data is edited after approval — fix it by invalidating (clearing `PdfFileId` in the sheet) on important mutations, or let the user press "Regenerate" themselves

## Rule #11: PDF export URL parameters — reference table

Every parameter of `/export?format=pdf` affects the resulting PDF layout, and Google does not document all of them in one place — here are the ones you actually use:

| param | common value | notes |
|---|---|---|
| `format` | `pdf` | required |
| `gid` | sheet ID (from `getSheetId()`) | required — omit it and every sheet in the spreadsheet is exported |
| `size` | `A4`, `letter`, `legal`, `0`-`9` | paper |
| `portrait` | `true` / `false` | portrait or landscape |
| `fitw` | `true` / `false` | fit the width — use `true` to stop columns from being cut off |
| `scale` | `1`-`4` | alternative to `fitw` — 1=normal, 4=fit the whole page |
| `gridlines` | `true` / `false` | gridlines (default true — usually not wanted in a PDF) |
| `printtitle` | `true` / `false` | print the spreadsheet name in the header |
| `sheetnames` | `true` / `false` | print the sheet name in the header |
| `pagenumbers` | `true` / `false` | page numbers |
| `top_margin`, `bottom_margin`, `left_margin`, `right_margin` | inches (`0.5`) | margin |
| `horizontal_alignment` | `LEFT`/`CENTER`/`RIGHT` | align the PDF content |
| `vertical_alignment` | `TOP`/`MIDDLE`/`BOTTOM` | |
| `range` | `A1:E20` | export only this range (omit = the whole sheet) |
| `r1`, `c1`, `r2`, `c2` | row/col indices (0-based) | alternative to `range` |
| `ir` | `false` | hide frozen rows when printing |
| `ic` | `false` | hide frozen columns |
| `fzr` | `true` / `false` | repeat frozen rows on every page |
| `fzc` | `true` / `false` | repeat frozen columns on every page |
| `attachment` | `true` / `false` | send the response as an attachment or inline |

### ✓ Recipe you will reuse most

```javascript
// one A4 portrait page, fit-width — e.g. a lesson record
function exportRecord_(ssId, gid, filename) {
  const params = {
    format: 'pdf',
    gid: gid,
    size: 'A4',
    portrait: true,
    fitw: true,
    gridlines: false,
    printtitle: false,
    sheetnames: false,
    pagenumbers: false,
    top_margin: 0.5,
    bottom_margin: 0.5,
    left_margin: 0.5,
    right_margin: 0.5,
  };
  return exportWithParams_(ssId, params, filename);
}

// Statement landscape A4
function exportStatement_(ssId, gid, filename) {
  return exportWithParams_(ssId, {
    format: 'pdf', gid: gid, size: 'A4',
    portrait: false, fitw: true,
    gridlines: false, sheetnames: false, pagenumbers: true,
    top_margin: 0.4, bottom_margin: 0.4, left_margin: 0.4, right_margin: 0.4,
  }, filename);
}

function exportWithParams_(ssId, params, filename) {
  const qs = Object.entries(params).map(([k, v]) => k + '=' + encodeURIComponent(v)).join('&');
  const url = 'https://docs.google.com/spreadsheets/d/' + ssId + '/export?' + qs;
  const resp = UrlFetchApp.fetch(url, {
    headers: { Authorization: 'Bearer ' + ScriptApp.getOAuthToken() },
    muteHttpExceptions: true,
  });
  if (resp.getResponseCode() !== 200) {
    throw new Error('PDF export failed: HTTP ' + resp.getResponseCode() + ' ' + resp.getContentText().substring(0, 200));
  }
  return resp.getBlob().setName(filename + '.pdf');
}
```

## Rule #13: PDF filename — use RecordID, not the display name

### ✗ Bad

```javascript
file.setName(record.SubjectName + '-' + record.ClassLevel + '-' + record.Topic + '.pdf');
```

```javascript
    .replace(/[\\/:*?"<>|]/g, '')  // forbidden in Drive
    .replace(/\s+/g, ' ')
    .trim()
    .substring(0, 100);
}
```

## Rule: appsscript.json must force a timezone + runtimeVersion: V8

```json
{
  "timeZone": "Asia/Bangkok",
  "exceptionLogging": "STACKDRIVER",
  "runtimeVersion": "V8",
  "webapp": {
    "executeAs": "USER_DEPLOYING",
    "access": "ANYONE_ANONYMOUS"
```

**Why V8:** it supports ES6+ (const/let, arrow functions, template literals, spread) — the old Rhino runtime does not

- per domain → PascalCase `Users.js`, `Records.js`
- global helpers → `Utils.js`
- no leading digits, no spaces (clasp pull/push will mangle them)

# PropertiesService (Script / User / Document properties)

## Rule #1: Pick the store at the right layer — Script vs User vs Document

| Store | Scope | Use for |
|---|---|---|
| `getScriptProperties()` | everyone using the script sees the same value | API key, system-level config, job checkpoint |
| `getUserProperties()` | separate value per Google account | personal preferences (language, default view) |
| `getDocumentProperties()` | bound to the file (for add-ons) | per-spreadsheet state inside an add-on |

**Gotcha:** a web app deployed with `executeAs: USER_DEPLOYING` + a user not signed into Google → `getUserProperties()` belongs to the **owner**, not the real user → a system with its own login (session token) must keep preferences in a Users sheet instead

---

## Rule #2: Criteria for choosing between Properties and a Config sheet

Both are key-value stores — choose based on **who needs to edit the value**:

| Store it in | When | Examples |
|---|---|---|
| **Script Properties** | secrets / values only a developer edits | API token (LINE, OpenAI), salt, job cursor |
| **Config sheet** | values a user-side admin must be able to edit without opening the script editor | folder ID, admin email, current academic year, announcement text |

**Why:** a Config sheet is editable from the Sheet page admins already know (the same principle as `rules/drive-ops.md` Rule #1) but **never put a secret in a Config sheet** — the sheet can be shared with other people, while Script Properties are readable only by people with script edit rights

```javascript
// secret → Script Properties
const token = PropertiesService.getScriptProperties().getProperty('LINE_CHANNEL_TOKEN');

// admin-editable → Config sheet
const folderId = getConfig_('PDF_FOLDER_ID');
```

---

## Rule #3: Know the limits — 9KB/value, 500KB/store — never use it as a database

**Why:** Properties is a config store, not a database — storing a big JSON blob (a record list, a query result cache) randomly hits `Argument too large` as the data grows

- Real data → Sheet
- Temporary cache → `CacheService` (100KB/key, has a TTL — see `rules/cache-service.md`)
- Properties → short config values + checkpoints

---

## Rule #4: To read several values use `getProperties()` once — and cache it

**Why:** every `getProperty()` is a round-trip (tens of ms slower than a variable) — a function that reads 5 properties on every call is slow for no reason

```javascript
let _propsCache = null;
function getProps_() {
  if (!_propsCache) _propsCache = PropertiesService.getScriptProperties().getProperties();
  return _propsCache; // cached per execution — a new execution always re-reads
}
```

---

## Rule #5: Configure secrets through the UI or a setup function you delete afterwards — never leave them in source

```javascript
// ✗ Bad — the token stays in git history forever
function setup() {
  PropertiesService.getScriptProperties().setProperty('LINE_CHANNEL_TOKEN', 'AbCdEf123...');
}
```

**✓ Good — 2 ways:**
1. **UI:** Apps Script editor → Project Settings ⚙️ → Script properties → Add property (no code involved at all)
2. **Temporary:** write a setup function → run it once → **delete the code before committing** (easy to forget — the UI route is safer)

# Schema Migrations — Adding tables/columns without breaking existing data

## Rule #1: idempotent `ensureSchema()` — must be safe no matter how many times it runs

**Why:** cloning the project → setup has to run; a new deploy → new columns have to be added; an existing user opening it → nothing old must break

### ✓ Good — declarative schema + ensure helpers

```javascript
const SHEET_NAMES = {
  CONFIG: 'Config',
  USERS: 'Users',
  RECORDS: 'Records',
  FOLDERS: 'Folders',
  AUDIT: 'Audit',
};

const SCHEMA = {
  Config: ['Key', 'Value'],
  Users: ['UserID', 'Username', 'DisplayName', 'Role', 'PasswordHash', 'PasswordSalt', 'Active', 'SignatureFileId', 'CreatedAt'],
  Records: ['RecordID', 'Timestamp', 'FolderID', 'TeacherUserID', 'Term', 'Year', /* ... */],
  Folders: ['FolderID', 'TeacherName', 'Subject', 'ClassLevel', 'Timestamp', 'OwnerUserID'],
  Audit: ['Timestamp', 'Actor', 'Action', 'Target', 'Detail'],
};

function ensureSchema() {
  const ss = SpreadsheetApp.openById(SPREADSHEET_ID);
  for (const name in SCHEMA) {
    ensureSheet_(ss, name, SCHEMA[name]);
  }
  ensureConfigEntry_(ss, 'TEACHERS_FOLDER_ID', () => createDriveFolderIfMissing_('TPM_Teachers'));
  ensureConfigEntry_(ss, 'SIGNATURES_FOLDER_ID', () => createDriveFolderIfMissing_('TPM_Signatures'));
}

function ensureSheet_(ss, name, headers) {
  let sh = ss.getSheetByName(name);
  if (!sh) {
    sh = ss.insertSheet(name);
    sh.getRange(1, 1, 1, headers.length).setValues([headers])
      .setFontWeight('bold').setBackground('#d81b60').setFontColor('white');
    sh.setFrozenRows(1);
  } else {
    // append any missing columns at the end of the table
    for (const h of headers) ensureColumn_(sh, h);
  }
  return sh;
}

function ensureColumn_(sheet, headerName) {
  const lastCol = sheet.getLastColumn() || 1;
  const headers = sheet.getRange(1, 1, 1, lastCol).getValues()[0].map(String);
  if (headers.indexOf(headerName) >= 0) return;
  sheet.getRange(1, lastCol + 1).setValue(headerName)
    .setFontWeight('bold').setBackground('#d81b60').setFontColor('white');
}
```

# Security

## Rule #1: Every server function the client can call needs `requireUser_` + `requireRole_`

**Why:** a web app deployed with `executeAs: USER_DEPLOYING` runs with the owner's rights — Google gives you no per-request auth from the user's side

### ✓ Good — guard every function

```javascript
function deleteRecord(callerUserId, recordId) {
  // Reference the record by RecordID, not by the row number sent from the client — rows shift all the time
  // (if someone deleted an earlier row → that same row number now points to a different record = wrong row deleted)
  const lock = LockService.getScriptLock();
  try {
    if (!lock.tryLock(10000)) throw new Error('System is busy, please try again');
    const caller = requireUser_(callerUserId);
    if (!recordId || typeof recordId !== 'string') throw new Error('Record not found');

    const record = readSheet_(sheet).find(r => String(r.RecordID) === recordId);
    if (!record) throw new Error('Record not found');

    // a teacher can delete only their own records
    if (caller.Role === 'teacher' && String(record.TeacherUserID) !== String(caller.UserID)) {
      throw new Error('No permission to delete');
    }
    // admin/supervisor can delete anything

    sheet.deleteRow(record.__rowIndex); // row index from the fresh read, taken under the lock
    return { ok: true };
  } catch (err) {
    return { ok: false, message: err.message };
  } finally {
    lock.releaseLock();
  }
}

function requireUser_(callerUserId) {
  if (!callerUserId) throw new Error('Not logged in');
  const user = findUserById_(callerUserId);
  if (!user) throw new Error('User not found');
  if (user.Active === false || user.Active === 'false') throw new Error('Account is disabled');
  return user;
}

function requireRole_(user, allowedRoles) {
  if (!Array.isArray(allowedRoles)) allowedRoles = [allowedRoles];
  if (!allowedRoles.includes(user.Role)) throw new Error('No permission');
}
```

## Rule #2: Accept that `callerUserId` can be faked — for high-stakes work use a session token

**Limit of the token-as-userId pattern:** the client stores the userId in localStorage — anyone can edit it and drop in an admin's userId

### For internal / low-stakes work → OK

### For sensitive work → use a session token + expiry

```javascript
// Login: the server creates the token and stores it in the Session sheet with userId + expiry
function login(username, password) {
  const user = verifyPassword_(username, password);
  if (!user) return { ok: false, message: 'Wrong username/password' };

  const token = Utilities.getUuid();
  const expiresAt = Date.now() + 8 * 60 * 60 * 1000; // 8 hr
  appendRowByHeaders_(getSessionSheet_(), {
    Token: token,
    UserID: user.UserID,
    ExpiresAt: expiresAt,
    CreatedAt: new Date().toISOString(),
  });
  return { ok: true, token: token, userId: user.UserID, role: user.Role };
}

// every server function takes a token instead of a userId
function requireSession_(token) {
  if (!token) throw new Error('Not logged in');
  const sessions = readSheet_(getSessionSheet_());
  const s = sessions.find(r => r.Token === token);
  if (!s) throw new Error('Session expired');
  if (Number(s.ExpiresAt) < Date.now()) throw new Error('Session expired');
  return findUserById_(s.UserID);
}
```

Trade-off: one extra sheet write per login + you must purge expired sessions with a trigger

## Rule #3: Store passwords/PINs as salted + peppered hashes — never iterate HMAC thousands of times

**Why:** GAS has no `crypto.subtle`, and `Utilities.computeHmacSha256Signature` is slow (several milliseconds per call) — 10,000 PBKDF2-style rounds leaves the PIN confirm button stuck on "Checking…" for almost a minute (seen for real in an expense-tracking app), and for a 4–6 digit PIN extra rounds buy nothing once someone has the hash (they can try every value in seconds anyway). What actually helps is a **pepper that is not in the sheet** and **limiting the number of failed attempts**

### ✗ Bad — stretching in GAS

```javascript
function hashPassword_(password, salt) {
  let bytes = Utilities.newBlob(password).getBytes();
  const saltBytes = Utilities.newBlob(salt).getBytes();
  for (let i = 0; i < 10000; i++) {            // ✗ nearly a minute per single login
    bytes = Utilities.computeHmacSha256Signature(bytes, saltBytes);
  }
  return Utilities.base64Encode(bytes);
}
```

### ✓ Good — one HMAC call: key = pepper in Script Properties, data = salt + password

```javascript
// the pepper is created once at setup (inside LockService so two people creating it at once don't overwrite each other) — it lives in Script Properties
// only, never in the sheet: someone who gets the whole spreadsheet still cannot guess the hash
function pepper_() {
  const props = PropertiesService.getScriptProperties();
  let p = props.getProperty('AUTH_PEPPER');
  if (p) return p;
  const lock = LockService.getScriptLock();
  lock.waitLock(10000);
  try {
    p = props.getProperty('AUTH_PEPPER');
    if (!p) {
      p = Utilities.getUuid() + Utilities.getUuid();
      props.setProperty('AUTH_PEPPER', p);
    }
    return p;
  } finally {
    lock.releaseLock();
  }
}

function hashPassword_(password, salt) {
  const sig = Utilities.computeHmacSha256Signature(salt + ':' + password, pepper_());
  return Utilities.base64Encode(sig);               // ✓ one call, sub-millisecond
}

function generateSalt_() {
  return Utilities.getUuid();
}

// On create user
const salt = generateSalt_();
const hash = hashPassword_(password, salt);
// store: PasswordHash, PasswordSalt

// On login
const expected = hashPassword_(inputPassword, user.PasswordSalt);
if (expected !== user.PasswordHash) throw new Error('Wrong password');
```

**Must be paired with:** limit the number of failed attempts — count per user in CacheService (e.g. 5 misses in 15 minutes → reject until the window expires), because with a short PIN this is the real defense, not hash slowness

- If you genuinely need stretching (long admin passwords), cap it at 100–300 rounds and measure the real time in GAS first
- Never store PINs/passwords as plain text, and never keep the pepper in a sheet or in the code

## Rule #4: oauthScopes in appsscript.json — request only what you use

**Why:** requesting more than necessary → scary prompts at authorize time + failed audits in enterprise

```json
{
  "oauthScopes": [
    "https://www.googleapis.com/auth/spreadsheets",          // read/write Sheets
    "https://www.googleapis.com/auth/drive",                 // for DriveApp (createFile/createFolder etc.) — DriveApp does not accept drive.file
    "https://www.googleapis.com/auth/script.external_request",  // UrlFetch
    "https://www.googleapis.com/auth/userinfo.email"         // read the user email
  ]
}
```

**Scope hierarchy (narrow → broad):**
- `drive.file` — only files the script created / files the user picked with a picker — **cannot be used with `DriveApp`**, only when you call the Drive REST API yourself (`UrlFetchApp` + `ScriptApp.getOAuthToken()`), with Advanced Drive Service, or with Google Picker
- `drive.readonly` — read the whole Drive ← use when `DriveApp` only reads (`getFileById`, `getFolderById`)
- `drive` — full access ← **required every time `DriveApp` writes** (`createFile`, `createFolder`, `Folder.createFile`, `setSharing`, `setTrashed`)

**DriveApp vs `drive.file` (seen for real):** declare `drive.file`, then call `DriveApp.createFolder()` → runtime error `The permissions specified are insufficient to call DriveApp.createFolder; the required permission is https://www.googleapis.com/auth/drive` (in English: "The script does not have permission to perform that action. Required permissions: https://www.googleapis.com/auth/drive") — the `DriveApp` reference lists only `auth/drive` as the scope for `createFile` / `createFolder`. If you use `DriveApp` to write files, just declare `drive`; don't guess `drive.file` because it looks narrower

## Rule #1: read the sheet once with `getDataRange().getValues()`

**Why:** every `getValue()`/`getRange()` call is a round-trip to the Google server — 1 sheet × 100 rows × 10 cols = 1,000 calls = you blow past the quota timeout (6 min)

### ✗ Bad — N+1 calls

```javascript
for (let i = 2; i <= sheet.getLastRow(); i++) {
  const id = sheet.getRange(i, 1).getValue();  // round-trip
  const name = sheet.getRange(i, 2).getValue(); // round-trip
  // ...
}
```

### ✓ Good — bulk read

```javascript
function readSheet_(sheet) {
  if (!sheet) return [];
  const data = sheet.getDataRange().getValues(); // 1 round-trip
  if (data.length <= 1) return [];
  const headers = data[0];
  const rows = [];
  for (let i = 1; i < data.length; i++) {
    const o = {};
    for (let j = 0; j < headers.length; j++) o[headers[j]] = data[i][j];
    o.__rowIndex = i + 1; // 1-based sheet row, for later updates
    rows.push(o);
  }
  return rows;
}
```

---

## Rule #2: never call `range.setValues()` on a sheet that may contain merged cells

**Why:** `range.setValues(values)` throws `Exception: Service error: Spreadsheet` (Spreadsheet service error) if the range contains merged cells — Sheets does not allow writing multiple values across a single merge

This is a bug you actually hit with **PDF templates that use placeholders** (`{{PLACEHOLDER}}`) — almost every template has a merged header row

### ✗ Bad

```javascript
const range = sheet.getDataRange();
const values = range.getValues();
// ...modify values...
range.setValues(values); // 💥 if merged cells are present
```

### ✓ Good — per-cell setValue only where something changed

```javascript
const range = sheet.getDataRange();
const values = range.getValues();
for (let r = 0; r < values.length; r++) {
  for (let c = 0; c < values[r].length; c++) {
    const orig = values[r][c];
    // ...compute next...
    if (next !== orig) {
      try {
        sheet.getRange(r + 1, c + 1).setValue(next);
      } catch (e) {
        Logger.log('skip r=' + (r + 1) + ' c=' + (c + 1) + ': ' + e.message);
      }
    }
  }
}
```

**Trade-off:** per-cell writes are slow (1 round-trip per cell) — fine for PDF templates where only a few dozen cells change, but **never use them on data tables with thousands of cells** (hits the 6-minute limit)

### ✓ Better for large ranges — check merged ranges first, then batch-write only the safe zones

```javascript
function hasMergedCells_(range) {
  return range.getMergedRanges().length > 0;
}

const range = sheet.getDataRange();
if (!hasMergedCells_(range)) {
  range.setValues(values);          // no merges → batch write, fastest
} else {
  // merges exist (usually the top header rows of a template) → batch write only the data part
  const dataRange = sheet.getRange(headerRows + 1, 1, values.length - headerRows, values[0].length);
  if (!hasMergedCells_(dataRange)) {
    dataRange.setValues(values.slice(headerRows));
  } else {
    // merges scattered everywhere → fall back to per-cell writes for changed cells only (see above)
  }
}
```

## Rule #6: handling Date objects — three traps to watch

Dates in GAS break easily because they cross 3 boundaries: **Sheet ↔ GAS server ↔ client browser** — and each boundary has its own gotcha

### #6.1 — `google.script.run` does not serialize `Date` objects → the client receives `{}`

```javascript
// ✗ Bad
function getRecord() {
  return { Timestamp: new Date() }; // client gets an empty {}
}

// ✓ Good — convert to an ISO string before sending to the client
function sanitizeForClient_(obj) {
  const out = {};
  for (const k in obj) {
    if (k === '__rowIndex') continue;
    const v = obj[k];
    if (v instanceof Date) out[k] = v.toISOString();
    else if (v && typeof v === 'object' && !Array.isArray(v)) out[k] = sanitizeForClient_(v);
    else out[k] = v;
  }
  return out;
}
```

### #6.2 — a Sheet cell of Date type comes back as a Date object, not a string

`getDataRange().getValues()` returns the cell type as Sheets stored it — if a user types `28/5/2026`, **Sheets converts it to a Date object** (not the string "28/5/2026")

```javascript
// ✗ Bad — assume string always
const ts = row.Timestamp;
console.log(ts.indexOf('2026')); // 💥 if ts is a Date — .indexOf is not a function

// ✓ Good — normalize every time
function toIsoOrEmpty_(v) {
  if (!v) return '';
  if (v instanceof Date) return isNaN(v.getTime()) ? '' : v.toISOString();
  const d = new Date(v);
  return isNaN(d.getTime()) ? String(v) : d.toISOString();
}
```

### #6.3 — Timezone trap: GAS server vs spreadsheet vs client

3 timezones that can differ:
- **Script timezone** — set in `appsscript.json` (`"timeZone": "Asia/Bangkok"`)
- **Spreadsheet timezone** — File → Settings → Time zone (may differ from the script's!)
- **Client browser** — the user's TZ

```javascript
// ✗ Bad — toLocaleDateString() uses the server TZ, not the user's
const display = new Date().toLocaleDateString('th-TH');

// ✓ Good — force the TZ you want
const display = Utilities.formatDate(new Date(), 'Asia/Bangkok', 'dd/MM/yyyy HH:mm');
// → "28/05/2026 14:30"

// ✓ Good — send ISO to the client and let the client format it (per locale)
return { ts: new Date().toISOString() }; // ISO = UTC
```

### #6.4 — store timestamps in the sheet as ISO strings, not Date type

**Why:** a Date type cell is rendered according to the **spreadsheet timezone** + the cell's display format — if an admin changes the spreadsheet TZ, the value shifts

```javascript
// ✗ Risky — store a Date object
appendRowByHeaders_(sh, { Timestamp: new Date() });
// Sheet renders in the spreadsheet TZ — change the TZ → value shifts

// ✓ Robust — store an ISO string (TZ-aware, never shifts)
appendRowByHeaders_(sh, { Timestamp: new Date().toISOString() });
// "2026-05-28T07:30:00.000Z" — fixed value, independent of the sheet TZ
```

But you must set the **column format to Plain text** first — otherwise Sheets may auto-parse the ISO string into a Date

### #6.5 — parse user input that may be a date in several formats

```javascript
function parseThaiDate_(input) {
  if (input instanceof Date) return input;
  const s = String(input || '').trim();
  if (!s) return null;

  // ISO: 2026-05-28T... or 2026-05-28
  if (/^\d{4}-\d{2}-\d{2}/.test(s)) return new Date(s);

  // dd/MM/yyyy or dd/MM/yy (Buddhist Era years also work)
  const m = s.match(/^(\d{1,2})[\/-](\d{1,2})[\/-](\d{2,4})$/);
  if (m) {
    let [, d, mo, y] = m;
    y = parseInt(y);
    if (y > 2400) y -= 543;          // Buddhist Era → Gregorian
    else if (y < 100) y += 2000;     // 2-digit year
    return new Date(y, parseInt(mo) - 1, parseInt(d));
  }
  return null;
}
```

## Rule #6.6: force numeric fields with leading zeros to be text — prevent zero loss

**Real bug:** storing phone number `0812345678` in a Sheet → becomes `812345678` (the leading 0 disappears) because Sheets auto-parses it as a number

Fields to watch:
- phone numbers (`08x-xxx-xxxx`)
- 13-digit national ID numbers (may start with 0 in some cases)
- postal codes (`10110` is fine but `01234` → `1234`)
- bank account numbers
- PO / invoice numbers with a prefix (`PO0001`, `INV0042`)
- teacher/student IDs (`T0001`, `S0042`)
- numeric RecordIDs (we have seen `0001` turn into `1`)

### Approach 1: set column format = Plain text first (recommended)

```javascript
function ensureTextColumn_(sheet, headerName) {
  const col = colIndex_(sheet, headerName);
  const lastRow = Math.max(sheet.getMaxRows(), 1000);
  sheet.getRange(1, col, lastRow, 1).setNumberFormat('@');
}

// call inside ensureSchema()
function ensureSchema() {
  const sh = ss.getSheetByName('Users');
  ensureColumn_(sh, 'Phone');
  ensureColumn_(sh, 'NationalId');
  ensureColumn_(sh, 'EmployeeCode');

  ensureTextColumn_(sh, 'Phone');         // 📌
  ensureTextColumn_(sh, 'NationalId');    // 📌
  ensureTextColumn_(sh, 'EmployeeCode');  // 📌
}
```

`setNumberFormat('@')` = `@` is the text format code — numbers are stored as plain strings, never parsed

### Approach 2: prefix the value with `'` (apostrophe)

```javascript
// ✗ Bad
sh.getRange(row, col).setValue('0812345678'); // still auto-parsed → 812345678

// ✓ Good — leading apostrophe forces the sheet to store text
sh.getRange(row, col).setValue("'" + phone);  // stores "0812345678" correctly
// the sheet does not display the apostrophe (it is an escape character)
```

**Caveat:** if you use `appendRow([...])` or `setValues([[...]])` with several values at once — you must add the apostrophe to every cell that should be text

### Approach 3: helper for append that forces text on specified fields

```javascript
const TEXT_FIELDS = ['Phone', 'NationalId', 'EmployeeCode', 'StudentId', 'PostalCode'];

function appendRowSafe_(sheet, obj) {
  const headers = sheet.getRange(1, 1, 1, sheet.getLastColumn()).getValues()[0];
  const row = headers.map(h => {
    const v = obj[h];
    if (v == null) return '';
    // store numeric fields that may have leading zeros as text
    if (TEXT_FIELDS.includes(h) && /^\d/.test(String(v))) {
      return "'" + String(v);
    }
    return v;
  });
  sheet.appendRow(row);
}
```

### ✓ Defense in depth — use both column format + apostrophe

```javascript
// 1. ensureSchema sets column format = '@'
ensureTextColumn_(sh, 'Phone');

// 2. helper adds the apostrophe on write
appendRowSafe_(sh, { Phone: payload.phone });

// 3. validate input on the server
if (!/^0\d{8,9}$/.test(payload.phone)) throw new Error('Invalid phone number');
```

### ⚠️ Pitfall: a format set later does not apply retroactively

If the sheet already holds data and the format is `Automatic`, the number `0812345678` has already been parsed into `812345678`
Calling `setNumberFormat('@')` afterwards **will not bring the leading zero back** — the cell already holds the number 812345678

**Do:**
```javascript
// migration: put the 0 back on phones that lost it
function migratePhoneFormat_(sh) {
  ensureTextColumn_(sh, 'Phone');
  const col = colIndex_(sh, 'Phone');
  const lastRow = sh.getLastRow();
  if (lastRow < 2) return;
  const range = sh.getRange(2, col, lastRow - 1, 1);
  const values = range.getValues();
  let changed = false;
  for (let i = 0; i < values.length; i++) {
    const v = values[i][0];
    if (typeof v === 'number' || /^\d+$/.test(String(v))) {
      const s = String(v);
      if (s.length === 9) { // 9 digits = probably lost the leading 0
        values[i][0] = "'0" + s;
        changed = true;
      }
    }
  }
  if (changed) range.setValues(values);
}
```

### ⚠️ Pitfall: setValues with an array is auto-parsed too

```javascript
// ✗ Bad — "0812345678" in an array is parsed into 812345678 before the write
sh.getRange(2, 1, 1, 2).setValues([['0812345678', '0123456789012']]);

// ✓ Good — apostrophe on every cell
sh.getRange(2, 1, 1, 2).setValues([["'0812345678", "'0123456789012"]]);
```

## Rule #7: numeric columns displayed as % — store as string, not number

**Why:** if the column format = `0%` and you write the number `100`, Sheets converts it to `10000%`
If the format = `0"%"` (text suffix), writing `100` gives `100%`

**The safe route:** write the string `"100.00"` + set the column format to `Plain text` or `0.00"%"`

## Rule #8: recompute on the server — never trust values from the client

**Real bug we hit:** the client computed `(pass/total)*100 = 500%` (because total changed while filling the form) and the server stored it as-is

### ✓ Good

```javascript
function saveRecord(callerUserId, payload) {
  const total = parseInt(payload.totalStudents) || 0;
  let pass = parseInt(payload.passCount) || 0;
  if (pass > total) pass = total; // clamp
  const fail = Math.max(0, total - pass);
  const passPct = total > 0 ? ((pass / total) * 100).toFixed(2) : '0.00';
  // use the recomputed value, not payload.passPercent
}
```

```javascript
async function test_generatePdf() {

    }),
  });
  const data = await res.json();
  console.assert(data.ok === true, 'expected ok=true, got:', data);
  console.log('✓ generatePdf returns', data.pdfFileId);
}

test_generatePdf().catch(e => { console.error(e); process.exit(1); });
```

You must implement `doPost(e)` that dispatches by function name — **the allow-list is always part of the dispatcher** (a dispatcher that calls `globalThis[name]` directly = anyone can call any internal function, including `_test_*` and helpers that skip auth):

```javascript
const RPC_ALLOWED = ['login', 'saveRecord', 'generatePdfForRecord' /* ... */];

function doPost(e) {
  try {
    const { function: name, args } = JSON.parse(e.postData.contents);
    if (!RPC_ALLOWED.includes(name)) throw new Error('forbidden: ' + name);
    const result = globalThis[name](...args);
    return ContentService.createTextOutput(JSON.stringify(result))
      .setMimeType(ContentService.MimeType.JSON);
  } catch (err) {
    return ContentService.createTextOutput(JSON.stringify({ ok: false, message: err.message }))
      .setMimeType(ContentService.MimeType.JSON);
  }
}
```

## Rule #11: never let `| grep` mask the test exit code in a deploy command

**Why:** `npm test | grep 'fail'` returns the exit code of **grep**, not the tests — `clasp deploy` once shipped to production while 3 tests were failing, because the pipe hid it

```bash
# ✗ Bad — grep's exit code masks the tests, && always passes
node --test tests/ | grep -E '^# (pass|fail)' && clasp push && clasp deploy -i "$DEPLOY_ID"

# ✓ Good — the tests decide, output is discarded
node --test tests/ > /dev/null && clasp push && clasp deploy -i "$DEPLOY_ID"

# ✓ Good — if you want the summary too, use PIPESTATUS (bash) or pipefail
set -o pipefail
node --test tests/ | tail -20 && clasp push
```

**Edge case:** the same applies to every pipeline that gates a deploy — `tee`, `head`, `sort` all mask the exit code

# Triggers (Time-driven / Installable)

## Rule #1: An install trigger must delete the old one first — prevent duplicate triggers

**Why:** calling `ScriptApp.newTrigger(...).create()` again (e.g. running setup twice) gives you **many overlapping triggers** — one job runs 2-3 times at once, data duplicates / emails send twice, and debugging becomes very hard because the logs do not show that it came from different triggers.

### ✗ Bad

```javascript
function setup() {
  ScriptApp.newTrigger('dailyReport').timeBased().everyDays(1).atHour(6).create();
  // run setup 3 times = 3 triggers = 3 reports sent
}
```

### ✓ Good — idempotent: delete the old ones pointing at the same function first

```javascript
function ensureTrigger_(handlerName, builderFn) {
  ScriptApp.getProjectTriggers()
    .filter(t => t.getHandlerFunction() === handlerName)
    .forEach(t => ScriptApp.deleteTrigger(t));
  builderFn();
}

function setup() {
  ensureTrigger_('dailyReport', () =>
    ScriptApp.newTrigger('dailyReport').timeBased().everyDays(1).atHour(6).create()
  );
}
```

**Limit:** max 20 installable triggers per script per user — going over throws at `create()`

---

## Rule #2: A trigger runs with the rights of the "installer" — not the sheet editor

**Why:** an installable `onEdit` or time-driven trigger runs as the installing account → `Session.getActiveUser()` may not be the person who edited the cell, and quota (e.g. email/day) is charged to the installing account.

- If you need to know who edited → use `e.user` (only available on the same Workspace domain) or keep a separate audit column
- Do not let multiple people install the same trigger — pick one central (service-account style) account as the installer

---

## Rule #3: Simple triggers (`onEdit`, `onOpen`) are limited — never rely on them for anything needing auth

**Why:** simple triggers run unauthorized — they cannot call `UrlFetchApp`, `MailApp`, `DriveApp` (they throw a permission error that is silent in the log)

| Need | Use |
|---|---|
| Format / validate a cell immediately on edit | simple `onEdit(e)` |
| Send email / call an API / write a Drive file when something changes | **installable** onEdit trigger |
| Scheduled work (daily/hourly) | time-driven trigger |

```javascript
// ✓ Install an installable onEdit
ScriptApp.newTrigger('onEditInstalled')
  .forSpreadsheet(SpreadsheetApp.getActive())
  .onEdit()
  .create();
```

---

## Rule #4: `onFormSubmit` — use `e.namedValues`, not `e.values`

**Why:** `e.values` is an array ordered by **column position** — the moment someone edits the form (adds/removes/moves a question) the indexes shift → you silently read the wrong fields (the same bug family as hardcoding column indexes in `rules/spreadsheet-ops.md` Rule #3)

### ✗ Bad

```javascript
function onFormSubmit(e) {
  const name = e.values[1];   // breaks the second someone reorders the form questions
  const phone = e.values[2];
}
```

### ✓ Good

```javascript
function onFormSubmit(e) {
  const name = (e.namedValues['Full name'] || [''])[0];
  const phone = (e.namedValues['Phone number'] || [''])[0];
  if (!name) { Logger.log('[onFormSubmit] missing name — form changed?'); return; }
  // ...
}
```

**Gotcha:** each key in `e.namedValues` is an **array** (a checkbox question can have multiple answers) — you must take `[0]` or `join(', ')` yourself

---

## Rule #5: A trigger handler needs a whole-body try/catch + an alert when it breaks

**Why:** a trigger runs when nobody is watching the screen — the exception vanishes into the Executions log until someone wonders "why has the report not arrived for 2 weeks?"

### ✓ Good

```javascript
function dailyReport() {
  try {
    Logger.log('[dailyReport] start');
    // ...the actual work...
    Logger.log('[dailyReport] done');
  } catch (err) {
    Logger.log('[dailyReport] EXCEPTION: ' + (err.stack || err));
    notifyAdminOnce_('dailyReport', err); // see rules/email-notifications.md Rule #4
  }
}
```

---

## Rule #6: Work inside a trigger that touches data shared with users — must also be in LockService

**Why:** a time-driven trigger and a user clicking a button in the web app can mutate the same sheet at the same time — triggers get no exemption from race conditions, use the same pattern as `rules/lock-service.md`

---

## Rule #7: Time-driven trigger times are a window, not an exact moment

**Why:** `atHour(6)` = runs sometime in 06:00–07:00 (Google spreads the load) — never design a job that must run at exactly 06:00

- Need minute-level accuracy → create a `everyMinutes(5)` trigger and check the time yourself in code, or use an external cron that calls `doGet`
- The `atHour` timezone = the timezone in `appsscript.json` — set `"timeZone": "Asia/Bangkok"` first or you get UTC times

---

## Rule #8: The app installs its own triggers on first setup — never tell the user to open the editor and run a function

**Why:** the classic "open the Apps Script editor and run `installTriggers()` once" instruction fails for anyone who is not a programmer (they do not know where the editor is, which function to pick) — so the system "never warned" even though the code was correct. Let the app install its own triggers at a moment when the owner is already using the app.

### ✓ Good — idempotent + flag + separate try/catch, called from the app's setup path

```javascript
// Safe to call many times without duplicate triggers (Rule #1) and remembers it ran
function ensureTriggers_() {
  const props = PropertiesService.getScriptProperties();
  if (props.getProperty('TRIGGERS_V') === '1') return { ok: true, already: true };
  ensureTrigger_('dailyReminder', () =>
    ScriptApp.newTrigger('dailyReminder').timeBased().everyDays(1).atHour(7).create()
  );
  props.setProperty('TRIGGERS_V', '1');            // bump to '2' when the trigger set changes
  return { ok: true, already: false };
}

// 1) On first setup: after the sheet / seed data is created (a setup path the owner clicks, or lazily on the owner's first app open)
function setupFirstRun() {
  const ss = getDataSpreadsheet_();
  // ...create tabs / header row...
  try {                                            // its own try/catch — if this fails the app page must still open
    ensureTriggers_();
  } catch (err) {
    Logger.log('[setup] triggers: ' + err);        // e.g. the owner has not granted the script.scriptapp scope
  }
}

// 2) Button / status on the app's settings page — let the user see that it is on, and repair it themselves if step 1 failed
function getTriggerStatus() {
  const on = ScriptApp.getProjectTriggers().some(t => t.getHandlerFunction() === 'dailyReminder');
  return { on, text: on ? 'On — checks every morning around 07:00' : 'Off' };
}
function enableTriggers() {                        // the "Enable automatic reminders" button in the UI
  try {
    ensureTriggers_();
    return getTriggerStatus();
  } catch (err) {
    throw new Error('Failed to enable: ' + err.message);   // the UI shows this message instead of failing silently
  }
}
```

- Declare `https://www.googleapis.com/auth/script.scriptapp` in `appsscript.json` from the start — the request then covers all scopes together at the owner's first open, instead of breaking later (see `rules/security.md` Rule #4)
- A trigger runs as the account that installed it (Rule #2) — in a web app running as the owner (`executeAs: USER_DEPLOYING`) whoever clicks the button, the trigger always belongs to the owner, which is correct
- Never call `ensureTriggers_()` on the main `doGet` path without a try/catch — an ungranted scope breaks the whole page

# UrlFetch & External API (LINE, webhook, REST)

## Rule #1: Always `muteHttpExceptions: true` + check the response code yourself

**Why:** the default for `UrlFetchApp.fetch()` is to **throw immediately** when the HTTP status ≥ 400 — you never see the response body that explains why (e.g. the error message from the LINE API), and the throw leaks to the client as a stack trace

### ✗ Bad

```javascript
const res = UrlFetchApp.fetch(url, opts); // 401 → throws, you have no idea the token expired
```

### ✓ Good

```javascript
function fetchJson_(url, opts) {
  opts = opts || {};
  opts.muteHttpExceptions = true;
  const res = UrlFetchApp.fetch(url, opts);
  const code = res.getResponseCode();
  const body = res.getContentText();
  if (code < 200 || code >= 300) {
    Logger.log('[fetchJson] ' + url + ' → HTTP ' + code + ' body=' + body.slice(0, 500));
    throw new Error('HTTP ' + code);
  }
  return body ? JSON.parse(body) : null;
}
```

---

## Rule #2: Retry + exponential backoff for transient errors (429/5xx)

**Why:** Google / LINE / external APIs transiently return 429 (rate limit) or 500/503 — giving up after one failure kills the entire batch for no reason, but **never retry other 4xx** (400/401/403 = resending fails exactly the same way)

### ✓ Good

```javascript
function fetchWithRetry_(url, opts, maxRetries) {
  maxRetries = maxRetries || 3;
  for (let attempt = 0; ; attempt++) {
    const res = UrlFetchApp.fetch(url, Object.assign({ muteHttpExceptions: true }, opts));
    const code = res.getResponseCode();
    const retryable = code === 429 || code >= 500;
    if (!retryable || attempt >= maxRetries) return res;
    Utilities.sleep(Math.pow(2, attempt) * 1000); // 1s, 2s, 4s
    Logger.log('[fetchWithRetry] retry ' + (attempt + 1) + ' after HTTP ' + code);
  }
}
```

**Careful:** `Utilities.sleep` consumes execution time (limit 6 minutes) — for large batches that retry often see `rules/long-running-jobs.md`

---

## Rule #3: For multiple requests use `fetchAll` — not a loop of single fetches

**Why:** `fetch()` in a loop = serial round-trips; `fetchAll()` fires them in parallel in one go, many times faster and counting the same quota

```javascript
const requests = userIds.map(id => ({
  url: 'https://api.example.com/users/' + encodeURIComponent(id),
  muteHttpExceptions: true,
}));
const responses = UrlFetchApp.fetchAll(requests);
responses.forEach((res, i) => {
  if (res.getResponseCode() !== 200) Logger.log('[sync] fail id=' + userIds[i]);
});
```

---

## Rule #4: Keep API keys/tokens in Script Properties — never hardcode them in source

**Why:** source gets committed / shared / pulled with clasp onto other machines — a hardcoded token leaks easily (see `rules/security.md` Rule #7 and the criteria for choosing where to store it in `rules/properties-service.md`)

```javascript
function getLineToken_() {
  const token = PropertiesService.getScriptProperties().getProperty('LINE_CHANNEL_TOKEN');
  if (!token) throw new Error('LINE_CHANNEL_TOKEN is not set in Script properties');
  return token;
}
```

## Rule #5: LINE Messaging API — a reusable pattern

```javascript
function pushLineMessage_(to, messages) {
  const res = UrlFetchApp.fetch('https://api.line.me/v2/bot/message/push', {
    method: 'post',
    contentType: 'application/json',
    headers: { Authorization: 'Bearer ' + getLineToken_() },
    payload: JSON.stringify({ to: to, messages: messages }),
    muteHttpExceptions: true,
  });
  const code = res.getResponseCode();
  if (code !== 200) {
    // LINE returns JSON explaining why, e.g. invalid user id / more than 5 messages
    Logger.log('[LINE] push fail HTTP ' + code + ' ' + res.getContentText());
    return { ok: false, message: 'Failed to send the LINE message' };
  }
  return { ok: true };
}

// Usage
pushLineMessage_(userId, [{ type: 'text', text: 'Your data has been saved' }]);
```

**Common gotchas:**
- `messages` must be an array of at most 5 items per call
- Sending to many people use `/multicast` (saves quota versus a push loop)
- LINE Notify is retired (March 2025) — new work uses the Messaging API only

## Rule #6: Watch quota — URL Fetch 20,000 calls/day (consumer)

| Account | URL Fetch calls/day |
|---|---|
| gmail.com | 20,000 |
| Google Workspace | 100,000 |

- A sync job that calls the API per row → 5,000 rows already burns 1 in 4 of the quota — aggregate requests (the destination API's batch endpoint) or cache the results (`rules/cache-service.md`)
- Once you hit quota `fetch` throws `Service invoked too many times` — catch that error and notify the admin instead of letting the job die silently

## Rule #7: The UrlFetch timeout is fixed at ~60 seconds — not configurable

**Why:** GAS has no timeout option — a slower destination API always throws `Timeout`

- Slow endpoint (generating a report on their side) → switch to the async pattern: fire the job → the destination calls back to our `doPost`, or poll the status periodically
- Never put a slow fetch inside an RPC the user is waiting on in the browser — the user sees a 60-second spinner and then a failure

# Web App RPC Pattern

A GAS web app calls server functions from the client via `google.script.run` — these are the patterns that scale

## Rule #1: every server function returns a `Result<T>` envelope — never throw

**Why:** if the server throws, the client only gets a raw `error.message` — and if the error happens deep in the stack, the message may be "Exception: Service error: Spreadsheet" (the user has no idea what that means)

### ✓ Good — envelope pattern

```javascript
function saveRecord(callerUserId, payload) {
  try {
    const caller = requireUser_(callerUserId);
    requireRole_(caller, ['teacher']);
    // ... mutation ...
    return { ok: true, recordId: recordId, message: 'Saved successfully' };
  } catch (err) {
    Logger.log('[saveRecord] ' + (err.stack || err));
    return { ok: false, message: err.message || String(err) };
  }
}
```

---

## Rule #2: client wrapper — promisify `google.script.run`

```javascript
function rpc(name, ...args) {
  return new Promise((resolve, reject) => {
    google.script.run
      .withSuccessHandler(resolve)
      .withFailureHandler(reject)
      [name](...args);
  });
}

// Usage
const res = await rpc('saveRecord', this.user.userId, payload);
if (res.ok) {
  Swal.fire('Success', res.message, 'success');
} else {
  Swal.fire('Error', res.message, 'error');
}
```

---

## Rule #3: identify the caller through a `callerUserId` parameter, not `Session.getActiveUser()`

**Why:** with a web app deployed as `executeAs: USER_DEPLOYING`, `Session.getActiveUser()` equals the deployment owner on every request — not the user who clicked the button

### ✓ Good — token-based caller

```javascript
// Client stores userId after login (localStorage is fine when stakes are low)
const res = await rpc('saveRecord', this.user.userId, payload);

// Server: validate callerUserId in every function
function requireUser_(callerUserId) {
  if (!callerUserId) throw new Error('Not logged in');
  const user = findUserById_(callerUserId);
  if (!user) throw new Error('User not found');
  if (user.Active === false || user.Active === 'false') throw new Error('Account is disabled');
  return user;
}

function requireRole_(user, allowedRoles) {
  if (!allowedRoles.includes(user.Role)) throw new Error('Permission denied');
}
```

**Limitation:** `callerUserId` is set on the client, so anyone can forge another user's ID — for work that needs real security you must store a session token + verify it (see `rules/security.md`)

---

## Rule #4: guard against oversized HTML payloads — RPC limit is 50MB

If you need to upload images/large files:
- images → base64 dataURL up to 5MB is normally enough
- large files → upload to Drive first, then send only the `fileId` to the server

### ✓ Good

```javascript
// Client: compress the image before sending
function compressImage(dataUrl, maxWidth = 1200) {
  return new Promise(resolve => {
    const img = new Image();
    img.onload = () => {
      const ratio = Math.min(maxWidth / img.width, 1);
      const canvas = document.createElement('canvas');
      canvas.width = img.width * ratio;
      canvas.height = img.height * ratio;
      canvas.getContext('2d').drawImage(img, 0, 0, canvas.width, canvas.height);
      resolve(canvas.toDataURL('image/jpeg', 0.85));
    };
    img.src = dataUrl;
  });
}
```

---

## Rule #5: bundle the initial load — one function call, many payloads

**Why:** every RPC = a ~300ms round-trip — 5 calls at boot = 1.5s

### ✗ Bad

```javascript
const me = await rpc('getMe', uid);
const folders = await rpc('listFolders', uid);
const records = await rpc('listRecords', uid);
const users = await rpc('listUsers', uid);
```

### ✓ Good

```javascript
// Server
function loadInitialBundle(callerUserId) {
  try {
    const caller = requireUser_(callerUserId);
    return {
      ok: true,
      me: sanitizeForClient_(caller),
      folders: listFolders_(caller),
      records: listRecords_(caller),
      users: caller.Role === 'admin' ? listUsers_() : [],
    };
  } catch (err) {
    return { ok: false, message: err.message };
  }
}

// Client
const bundle = await rpc('loadInitialBundle', this.user.userId);
```

## Rule #6: optimistic update — do not wait for the server just to render

```javascript
async doSaveReview() {
  const optimisticStatus = this.modal.reviewStatus;
  this.modal.record.AcademicStatus = optimisticStatus; // update the UI immediately
  try {
    const res = await rpc('updateRecordStatus', uid, rowIndex, optimisticStatus, comment);
    if (!res.ok) {
      // rollback
      Swal.fire('Error', res.message, 'error');
      this.refresh(false);
    }
  } catch (e) {
    this.refresh(false);
  }
}
```
